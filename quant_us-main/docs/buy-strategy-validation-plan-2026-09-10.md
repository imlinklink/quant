# 买入策略历史验证实验设计（2026-09-10）

## 1. 文档目的

本文件规定 `buy_strategy_v2` 的历史验证方法。实验开始后，策略定义、参数、样本划分、成本假设、股票池、排序方式和验收门槛全部冻结。任何修改必须创建新的实验版本，不能覆盖原实验结果。

本实验需要回答三个问题：

1. 日线 `trend_pullback` 和 `reversal_confirmed` setup 是否具备样本外预测能力；
2. 15 分钟执行择时是否相对“次日开盘买入”提供可重复的增量；
3. 哪种退出机制与 10–40 个交易日的中期持仓周期匹配。

实验结果用于决定是否把新 setup 接入 Entry shadow。它不直接授权模拟或真实交易。

## 2. 防止过拟合的强制规则

### 2.1 实验版本

首轮实验编号固定为：

```text
BUY-V2-EXP-001
```

必须保存以下内容的哈希：

- 策略代码提交；
- 配置文件；
- 股票池清单；
- 行情数据清单；
- 公司行动调整方式；
- 训练、验证、测试区间；
- 成本和滑点模型；
- 实验执行脚本版本。

输出目录：

```text
backtests/buy_v2/BUY-V2-EXP-001/
  manifest.json
  config.yaml
  universe.csv
  data_quality.csv
  signals.csv
  trades.csv
  rejected_signals.csv
  outcomes.csv
  metrics.json
  report.md
```

### 2.2 冻结协议

第一次查看验证集或测试集收益前，必须写入 `manifest.json`：

- 本文档版本；
- 所有参数；
- 数据区间；
- 验收标准；
- Git commit；
- 生成时间；
- 随机种子。

实验开始后禁止：

- 因测试结果不佳而修改阈值；
- 删除表现差的股票或年份；
- 根据全期收益选择退出参数；
- 用测试集决定 setup 条件；
- 将多个高度重叠窗口当成独立证据；
- 只报告最优参数，不报告完整矩阵；
- 覆盖旧实验目录。

需要修改时，创建 `BUY-V2-EXP-002`，说明修改依据。新实验仍沿用尚未查看的测试集，或者向后滚动到新的测试区间。

### 2.3 决策日志

建立：

```text
backtests/buy_v2/experiment-log.md
```

每次实验记录：

| 字段 | 内容 |
|---|---|
| experiment_id | 唯一实验编号 |
| parent_id | 基于哪个实验 |
| hypothesis | 修改前提出的假设 |
| change | 唯一主要变化 |
| expected_effect | 预期改善的指标 |
| allowed_data | 允许使用的数据区间 |
| result | 完成后填写 |
| decision | retain/reject/inconclusive |

每个新实验原则上只允许一个主要策略变化，否则无法归因。

## 3. 数据范围

### 3.1 时间范围

目标覆盖至少一个牛市、一个熊市和一个震荡阶段。首轮建议：

| 用途 | 区间 | 权限 |
|---|---|---|
| 开发期 | 2016-01-01～2020-12-31 | 可查看、调试实现 |
| 验证期 | 2021-01-01～2023-12-31 | 只用于选择策略家族，不做细粒度寻参 |
| 测试期 | 2024-01-01～2026-08-31 | 最后一次运行后才能查看 |
| 前向 shadow | 2026-09-01 起 | 完全样本外 |

如果可用数据不足以覆盖 2016 年，允许整体缩短，但必须在运行前固定边界，且测试期至少包含两个完整自然年。

### 3.2 数据频率

- 日线：setup、状态机、日线退出和基准收益；
- 15 分钟：执行择时、入场价和当日失效；
- 公司行动：统一采用前复权或 total-return 口径；
- SPY：市场基准；
- 行业代理：相对强度基准；
- 财报和重大事件：只能使用当时已经公开的信息；
- 期权数据：历史覆盖不足时只能作为缺失字段，不能用当前期权信息回填过去。

### 3.3 时间可用性

所有数据必须带：

- `event_time`：事件实际发生时间；
- `observed_at`：系统能够获得它的时间；
- `effective_session`：允许参与决策的交易日；
- `source` 和 `quality`。

日线在纽约常规交易时段收盘后才可用。15 分钟 bar 只有在 bar 结束后才可用。财报结果不能用于财报发布之前的 setup。

## 4. 历史时点股票池

### 4.1 禁止使用当前观察池作为唯一股票池

当前八只股票只能作为兼容性子样本，不能承担总体结论。主实验必须使用按历史日期确定的 universe。

每个交易日的股票必须满足：

- 当日已经上市；
- 当时未退市、停牌或进入不可交易状态；
- 价格和成交量满足预先定义的流动性门槛；
- 当时属于预先定义的行业范围或指数成员范围；
- 不使用未来市值、未来成交量或未来指数成分信息。

### 4.2 Universe 分层

至少分为：

| 分层 | 示例 | 目的 |
|---|---|---|
| 大中盘普通股票 | 标准美股 | 主策略结论 |
| 小盘普通股票 | AXTI 类 | 检查成本和跳空 |
| 次新股 | 上市不足两年 | 单独评价历史不足问题 |
| 杠杆 ETF | SOXL、YINN | 单独风险模型，不能混入普通股票 |
| 当前观察池 | 现有八只股票 | 与旧系统对照 |

普通股票与杠杆 ETF 必须分别报告，不允许用杠杆 ETF 的大幅收益抬高普通股票表现。

### 4.3 最低数据质量

每只股票、每个区间记录：

- 第一根和最后一根日线、15 分钟线；
- 理论交易日数和实际覆盖率；
- 重复、缺口、非正价格、异常成交量；
- 复权因子跳变；
- 退市和公司行动状态；
- 数据是否被 API 限流截断。

关键行情缺失或覆盖率低于 98% 的股票区间标记为 `quality_fail`，不产生交易，但仍保留在质量报告中。

## 6. A/B/C/D 主实验

四组必须使用完全相同的数据、股票池、组合约束和成本模型。

| 组 | 日线 setup | 入场方式 | 目的 |
|---|---|---|---|
| A | 无 | 旧 15 分钟 dip_buy | 旧系统基线 |
| B | 有 | 旧 dip_buy 分数触发 | 判断日线过滤能否改善旧信号 |
| C | 有 | setup 后下一交易日开盘 | 测量日线 setup 独立价值 |
| D | 有 | 新 15 分钟确认 | 测量分钟择时的增量 |

### 6.1 信号一致性

- B、C、D 必须来自同一批日线 setup；
- 如果 D 没有在 setup 有效期内触发，记录 `timing_missed`，不能删除；
- 如果 C 成交而 D 未成交，必须继续结算 D 的未成交反事实；
- A 的股票池和组合限制必须与其他组一致；
- 同一 setup 同一入场方法最多产生一笔交易。

### 6.2 主要比较

- B 对 A：日线资格过滤的价值；
- C 对 A：新日线 setup 的整体价值；
- D 对 C：15 分钟择时的独立增量；
- `trend_pullback` 与 `reversal_confirmed` 分开报告。

D 只有在成交价、MAE、止损率或风险调整收益上稳定优于 C 时，才保留 15 分钟执行模块。

## 7. 出场正交实验

先冻结每组的入场交易。随后对同一入场集合应用以下退出方式：

| ID | 退出方式 |
|---|---|
| E1 | 固定持有 5 个交易日 |
| E2 | 固定持有 10 个交易日 |
| E3 | 固定持有 20 个交易日 |
| E4 | 固定持有 40 个交易日 |
| E5 | -5% 固定止损 + 20 日时间退出 |
| E6 | 1.5ATR Chandelier |
| E7 | 2.0ATR Chandelier |
| E8 | 2.5ATR Chandelier |
| E9 | 3.0ATR Chandelier |
| E10 | higher-low 结构退出 |
| E11 | higher-low 与 2ATR 中较紧的一条 |
| E12 | 旧 8 根 15 分钟时间退出 |

E1–E12 必须完整报告。首轮不根据测试集选择最优退出；优先判断某个退出家族是否在多个年份和不同股票分层中保持同方向。

## 8. 组合级执行规则

回测采用单一时间线，禁止逐股回测后直接相加。

每个事件时点依次执行：

1. 处理已有硬止损和退出；
2. 更新已经完成的日线或 15 分钟数据；
3. 处理 setup 失效；
4. 收集所有新触发；
5. 根据冻结排序选择可成交信号；
6. 应用风险预算、行业上限和最多三仓；
7. 按可成交价格建仓；
8. 记录未成交原因和反事实。

### 8.1 同时信号排序

首轮排序固定为：

1. Selection `portfolio_rank` 升序；
2. 数据质量等级；
3. setup 状态：`CONFIRMED` 优先于 `REVERSING`；
4. 风险收益比降序；
5. 股票代码字典序。

不得使用事后收益排序。

### 8.2 成交假设

- 日线信号：下一交易日开盘成交；
- 15 分钟信号：信号 bar 完成后的下一根开盘成交；
- 入场 bar 当天即可触发原有止损；
- 跳空穿越止损按开盘价成交；
- 非跳空盘中触线按止损线加滑点成交；
- 保护线先检查旧值，再在 bar 完成后更新；
- 同一 bar 无法确定价格路径时，同时报告保守和乐观边界，主结果采用保守路径。

## 9. 成本和流动性压力测试

主结果使用 0.20% 往返成本，同时必须输出：

| 场景 | 往返成本 |
|---|---:|
| 理想 | 0.10% |
| 基准 | 0.20% |
| 压力 | 0.50% |
| 极端 | 1.00% |

另外按当时成交量和价格估算容量：

- 订单金额不得超过当根成交额的固定比例；
- 小盘股单独增加滑点压力；
- 盘前、盘后和常规时段分别建模；
- 不允许负价格改善；
- 每笔记录佣金、价差和滑点三项成本。

## 11. 统计方法

### 11.1 独立样本

同股票、同策略、同事件簇、同交易周的多个 setup 聚合为一个 independence group。置信区间和 bootstrap 以 independence group 为重采样单位，不能把高度重叠的逐笔交易当成完全独立样本。

### 11.2 必须报告

- 交易数与独立样本数；
- 毛、净期望及 95% bootstrap CI；
- 胜率及区间；
- 盈亏比；
- MFE、MAE；
- 最大回撤；
- 年度和 regime 分组；
- 股票和行业贡献；
- 前三笔、前两只股票利润集中度；
- 最大并发和资金占用；
- cost sensitivity；
- B-A、C-A、D-C 的配对差异及置信区间。

配对比较以同一 `setup_id` 为单位，不能拿不同信号集合的均值直接相减。

### 11.3 多重比较

E1–E12 属于多个候选退出方式。报告未经调整和经过 Holm 调整的显著性结果。任何“最优退出”都必须在下一实验或前向 shadow 中重新验证。

## 12. Walk-forward 设计

采用 anchored walk-forward：

| 训练数据 | 测试年份 |
|---|---|
| 起点～2020 | 2021 |
| 起点～2021 | 2022 |
| 起点～2022 | 2023 |
| 起点～2023 | 2024 |
| 起点～2024 | 2025 |
| 起点～2025 | 2026 |

首轮固定参数不做年度重选。Walk-forward 用于观察策略跨年份稳定性，不用于每年选择最优参数。

每折至少报告：

- setup 数和独立样本数；
- A/B/C/D 期望；
- D-C 配对差异；
- 各退出方式结果；
- 最大回撤；
- 股票贡献集中度。

## 13. Regime 分组

Regime 分类必须只使用当时可见数据，且在实验前冻结。至少包括：

- 市场趋势：SPY 高于/低于 MA200；
- 波动率：正常/高波动；
- 行业趋势：行业代理高于/低于 MA200；
- 个股类型：普通股票/小盘/次新/杠杆 ETF；
- setup 类型：pullback/reversal。

Regime 结果用于说明适用范围。不能看到结果后把亏损 regime 排除，再将剩余部分称为完整策略。

## 14. 验收门槛

### 14.1 日线 setup 晋级 Entry shadow

必须同时满足：

- 测试期和前向 shadow 的净期望为正；
- 95% CI 不表现为明显负值；
- 至少 20 个独立 setup 批次；
- 至少 50 个独立 setup 样本；
- 不少于 60% 的有效年份净期望为正；
- 成本提高至 0.50% 后策略未完全失效；
- 去掉最佳两只股票后结果不发生决定性反转；
- 前三笔盈利不超过总盈利的 40%；
- 最大回撤符合既定风险预算；
- 数据质量失败不会产生交易。

### 14.2 15 分钟 timing 保留条件

D 相对 C 必须满足至少一项主要条件，并且其他关键指标不显著恶化：

- 平均 MAE 至少改善 10%；
- 止损率至少下降 10%；
- 净期望提高且 D-C 配对 CI 不明显为负；
- 在至少 60% 的 walk-forward 折中方向一致。

如果 D 没有稳定优于 C，删除新分钟择时，直接使用 C 的日线次日开盘方式。复杂度本身不构成保留理由。

### 14.3 退出方式晋级条件

- 不依赖单一年份；
- 不依赖单只股票；
- 相邻 ATR 参数表现连续，不能是孤立最优点；
- 回撤和尾部损失符合预算；
- 在测试期和前向 shadow 中方向一致。

## 15. 失败与证伪条件

出现任一情况，应停止上线并回到研究阶段：

- C 相对 A 没有改善，说明日线 setup 无增量；
- D 显著差于 C，说明分钟择时有害；
- 收益仅来自当前观察池或两只股票；
- 去掉 2025–2026 后策略失效；
- 0.5% 成本使收益完全反转；
- 组合最多三仓后收益消失；
- 状态机存在前视或数据修订污染；
- 数据覆盖不足以形成可信测试期；
- 实验执行过程中曾查看测试结果并修改参数。

证伪是有效实验结果，不得通过继续添加过滤器隐藏。

## 16. 实验执行顺序

```text
1. 创建并冻结 manifest
2. 构建历史时点 universe
3. 生成数据质量报告
4. 缓存统一日线与15分钟数据
5. 生成全部日线状态和 setup
6. 生成 A/B/C/D 入场集合
7. 应用组合级三仓和风险预算
8. 对冻结入场运行 E1–E12
9. 结算固定 horizon outcome
10. 执行 bootstrap、集中度和成本压力测试
11. 运行 walk-forward
12. 一次性打开测试结果
13. 生成不可覆盖的最终报告
14. 登记 retain/reject/inconclusive
```

## 17. 自动化验收

实验 runner 必须在开始时拒绝以下情况：

- manifest 缺字段；
- 输出目录已存在且非空；
- Git 工作区与 manifest commit 不一致；
- 配置哈希不一致；
- 数据清单哈希不一致；
- 股票池包含上市前日期；
- 日线或分钟数据有未解释缺口；
- 测试区间早于训练区间结束；
- 成本矩阵不完整；
- A/B/C/D 任一组缺失；
- E1–E12 任一退出缺失。

运行完成后检查：

- 现金、持仓和已实现盈亏账本守恒；
- 任一时刻持仓不超过三个；
- 每笔成交均能追溯到 setup 或 A 组基线信号；
- 每个 setup 都有成交或未成交结果；
- 每个结果都有数据质量标记；
- 报告数字可由 trades/outcomes 文件独立复算。

## 18. 首轮报告结构

最终 `report.md` 固定包含：

1. 数据覆盖与排除情况；
2. A/B/C/D 核心结果；
3. D-C 配对增量；
4. `trend_pullback` 与 `reversal_confirmed` 分拆；
5. E1–E12 退出矩阵；
6. walk-forward；
7. regime；
8. 成本敏感性；
9. 利润集中度；
10. 失败案例；
11. 已知限制；
12. 按预先标准作出的 retain/reject/inconclusive 判定。
