# LLM全闭环决策路线图

日期：2026-09-17。核心目标：提升LLM在研究、买入、持仓、卖出及复盘中的实际作用，并衡量这些决策对账户结果的贡献。

本路线替代此前以回测实验和账户基础设施为中心的实施优先级。既有代码与验收成果继续复用。策略研究由另一个项目负责，本系统负责接入策略、组织LLM决策并可靠执行。当前状态依据最近一次代码检查，不代表已重新核对今日全部变更。

## 1. 什么才算实现目标

LLM接收当时可用的真实证据，输出明确动作；系统按权限应用动作；之后能追踪执行结果和收益影响。这才是一次完整的LLM决策闭环。

不以调用次数、报告长度或否决比例作为目标。有效决策也包括有依据地维持原计划；不能为了“提高占比”强迫模型干预。

目标链路：

```text
真实行情、公告与事件 + 策略项目的买卖信号
                    ↓
             冻结证据和规则原计划
                    ↓
      LLM研究 → 入场评审 → 持仓评审 → 退出评审
                    ↓
          权限映射 + 程序风险检查
                    ↓
              模拟／真实交易执行
                    ↓
          成交、持仓、净值与决策归因
                    ↓
           复盘 → 下一版本决策协议
```

## 2. 当前起点

已有Selection shadow、证据包、决策账本、执行与硬退出模块，以及R/L双影子账户原型。此前已进行恢复与双引擎一致性加固。

最近检查时，新双账户仍使用排程fixture与FakeModel；真实候选、真实模型和账户动作尚未完全贯通。旧链路已有LLM评审，不等于新闭环已接入，更不等于已证明收益增量。

因此下一步优先交付真实闭环，不继续扩大历史参数搜索。历史与影子对比只补足影响当前策略接入的正确性检查，不要求把全部研究问题解决后才能接模型。

## 3. 阶段路线

### M1：真实LLM入场决策闭环——最高优先级

**目标：让真实LLM首次在新闭环中改变一笔真实候选对应的模拟交易。**

交付内容：

- 接入一个固定策略版本的真实买入候选；外部策略尚未交付时，使用现有规则适配器推进，不等待寻找更优策略。
- 冻结规则原计划、行情时间、公告与事件证据；证据不足显式标记。
- 接入真实模型，输出PASS／VETO／ABSTAIN，替换FakeModel路径。
- R账户执行原规则；L账户应用LLM动作。VETO取消本次入场，ABSTAIN回到合格的父策略，不覆盖数据或风控拒绝。
- 保存输入、原始回复、校验结果、最终动作、成交及未成交原因。

验收：真实候选能贯通全部链路，模型输出确实影响L的计划；超时降级和重启不会重复调用或交易。若观察期内没有自然VETO，不强迫模型否决：真实PASS链路加确定性VETO执行测试分别留证，首次真实影响标记为待观察。

此阶段只开放模拟决策权限，不自动改变真实订单授权。

### M2：LLM研究与候选优先级

**目标：让LLM提供技术规则之外的信息，而不仅复述指标。**

交付内容：

- 每只候选形成投资逻辑、催化剂、反对证据和可观察的失效条件。
- 在程序已允许的候选池内排序；容量不足时研究其是否能改善机会选择。
- 新发现的股票进入研究观察池，先经身份、数据和策略资格检查，不直接获得交易资格。
- 公告原文、媒体转述及重复事件分开处理；发布时间与实际取得时间可追溯。

验收：排序和判断引用有效证据，能够明确说明相对规则新增了什么信息；排序动作与入场否决分别记录版本和贡献。先旁路输出，再单独开放排序影响，避免与M1同时改变导致无法归因。

### M3：LLM持仓管理与主动卖出

**目标：LLM不仅决定买不买，也持续判断还应不应该持有。**

交付内容：

- 买入时保存初始投资逻辑和失效条件；持仓期间按固定频率及重大事件触发复核。
- 输出HOLD／REDUCE／EXIT／ABSTAIN，并说明相较上次复核的新证据。
- REDUCE只映射为预设减仓档位，数量由程序计算；EXIT允许在规则退出之前主动建议卖出。
- 没有新证据时允许维持判断，不因为价格波动反复改变动作。
- 记录提前退出避免的损失与错过的后续收益，连同释放资金后的机会一起评价。

验收：持仓评审能实际改变模拟仓位；部分成交、重复触发和重启可对账。规则硬止损始终生效，LLM不能取消或推迟。

推迟规则卖出、延长最大持有期及放宽保护线不在首版权限内；如需研究，另开版本，不能以HOLD隐式覆盖规则退出。

### M4：把LLM影响从模拟扩展到受限实盘

**目标：验证有边界的LLM决策能够可靠转化为真实交易。**

真实行情及账户只读接入可与M1并行；小额真实订单联调无需等待全部M2/M3研究结束，但须先明确账户、联调资金、单笔金额、最大允许损失及停止方式，并完成订单幂等、未知成交恢复、硬退出和对账验收。

逐角色开放权限：先展示与人工确认，再允许已明确授权范围内的动作执行。每个角色独立开关、可撤回，不因买入评审通过就自动开放卖出或仓位权限。

验收：一次真实决策能追踪至订单和成交；明确区分模型原建议、人工覆盖、程序拦截与最终执行。首次小额成交只证明链路可用，不证明策略或LLM有效。

### M5：复盘与决策权限迭代

**目标：依据结果扩大有价值的权限，撤回无价值的干预。**

交付内容：

- 工程日报：数据、模型、决策、执行、对账是否闭合。
- 周度决策复盘：覆盖率、动作分布、证据质量、失败原因和人工覆盖。
- 按预登记观察窗口评价账户贡献；中长持有策略等待结果成熟，不把短期浮盈当成最终结论。
- LLM辅助归纳失败模式、提出改进假设；程序计算收益和风险，人确认下一版本。
- 模型、提示词、证据源及动作映射均版本化，禁止看见结果后改写旧决策。

验收：每个LLM角色都有“继续观察／保留／扩大权限／撤回影响”的明确结论。不能证明增量时保持有限权限，而不是继续叠加复杂度。

## 4. 权限边界

| 决策事项 | LLM作用 | 程序作用 |
|---|---|---|
| 信息与研究 | 解读事件、构建和修订投资逻辑 | 检查来源、时间、身份、数据质量 |
| 候选优先级 | 对合格候选排序 | 控制可交易池、容量与固定映射 |
| 入场 | 支持、否决或弃权 | 校验信号、价格、资金和风险 |
| 持仓 | 判断逻辑变化，建议保持或减仓 | 维护持仓事实及风险占用 |
| 卖出 | 建议主动减仓或提前退出 | 硬止损、数量计算、执行及成交对账 |
| 复盘 | 解释案例、提出可检验假设 | 计算绩效、保留版本和历史事实 |

LLM超时可以降级为父策略；账户不一致、关键行情失效或硬风控拒绝不能通过这种降级放行。模型自报信心不是胜率，不直接决定仓位。

## 5. 如何证明作用增强

| 指标 | 定义与用途 |
|---|---|
| 真实评审覆盖率 | 截止时间内取得有效真实模型评审的合格对象数／应评审对象数；入场和持仓分别统计 |
| 实际影响率 | 因LLM而改变最终计划的对象数／符合应用资格的对象数；不设必须达到的否决比例 |
| 执行兑现率 | 已批准应用的LLM动作中，执行完成或具有明确失败终态的比例 |
| 证据质量 | 引用有效性、时间正确性及抽样人工核对的论据支持程度 |
| 账户净贡献 | 共同风险约束下，LLM账户相对规则账户的全成本收益、回撤及资金暴露差 |
| 运行代价 | 模型成本、延迟、弃权、故障降级和人工介入次数 |

收益改善必须同时看错失机会，风险下降必须同时看暴露是否下降。被否决交易的反事实收益用于解释，不能简单相加当作账户增量。

多角色逐步启用：先记录纯规则对照，再增加入场评审；后续排序和持仓退出使用新版本及同期对照。不同市场阶段的前后收益差不能直接算作新增角色贡献。

## 6. 与策略研究项目的分工

策略项目负责验证买入、卖出、持有期和止损规则。本系统接收：策略ID与版本、股票池、输入需求、买卖信号、初始保护线、退出协议、成本假设及样例。

本系统负责验证实现是否忠实、真实数据能否及时产生信号、LLM如何改变动作、执行是否准确及结果归因。策略版本和LLM版本分开编号；研究需要升级时保留原对照，不静默替换。

现有B3候选基线可用于接入验证，不必等另一个项目研究结束。新策略到位后通过同一接口替换为新实验版本，不重建执行系统。

## 7. 实施顺序与停止扩展条件

近期只安排以下四个连续交付，避免再次把目标稀释：

1. **真实候选接口**：接一个固定策略版本，并保存规则原计划。
2. **真实LLM入场接口**：证据包、三态输出、截止时间和降级。
3. **真实双账户动作闭环**：LLM动作实际进入L；修复会阻断此路径的恢复和幂等问题。
4. **单次闭环报告**：展示从候选、证据、模型动作到账户变化的完整证据。

这四项完成，即可明确回答“LLM已进入真实数据驱动的模拟交易决策”。随后优先M3持仓与主动卖出，让买卖两端都有LLM参与；M2研究排序可以先旁路积累。M4执行接入并行推进，按明确授权开放真实交易影响。

不新增参数网格、多模型投票或大规模数据源工程，除非已有运行证据表明它阻断上述交付。角色有效性不足不阻止其他角色的只读研究，但阻止该角色扩大资金权限。

## 8. 下一次交付应回答的问题

- 今天有多少真实候选或持仓需要评审？
- LLM看到了哪些当时已知的证据？
- 它给出了什么动作，为什么？
- 动作是否改变了模拟或真实交易；没有改变的原因是什么？
- 后续结果如何，与原规则相比增加了什么收益、损失或风险？

下一项核心交付应是M1的可运行闭环及其证据，而不是另一轮泛化的策略优化。
