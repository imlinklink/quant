# 策略与 LLM 决策可视化页面需求

日期：2026-09-22  
状态：需求草案，供后续页面设计与开发使用；本次只交付文档。  
范围：美股项目 `quant_us-main`，以及与其关联的独立策略研究、纸面前向实验。

## 1. 页面要帮助用户回答什么

用户目标是挑选更有效的买入、卖出策略，让 LLM 产生可验证的决策贡献，并改善胜率、扣费收益与风险表现。页面应让用户无需读日志、SQL 或代码，就能回答：

1. 系统当前在运行哪些策略、哪些账户和实验？数据更新到什么时候？
2. 今天为什么买、为什么不买？没有交易是在等待机会，还是链路被阻断？
3. 每笔持仓为什么继续拿着，什么条件会卖，已经回吐了多少浮盈？
4. LLM 看到了什么、建议什么、真正改变了什么？没生效的原因是什么？
5. 新买卖策略与原策略相比，改善了什么、牺牲了什么？
6. LLM 相对同一规则基线，是否提供了扣除成本后的增量？
7. 现在需要用户处理什么，哪些项目只需继续观察？

首页优先回答这些问题。调用次数、模块数量、测试数量与长篇模型解释不作为主要成果展示。

## 2. 现有界面与信息缺口

本次依据模板、Web 路由、报告模块及最新交付记录检查，未做运行中浏览器验收，也未重新核对实时账本。以下“缺口”表示现有页面没有形成完整展示，不等于底层完全没有数据。

| 现有入口 | 已有信息 | 还需要补足的信息 |
|---|---|---|
| `/` 行情页 | 行情、K 线分析、信号与评分 | 跨策略的机会流转、没有交易的原因、账户与实验状态 |
| `/approvals` 确认台 | 买卖提案、规则理由、计划、模型建议、生效动作、权限、部分健康信息与输入快照 | 提案前后的完整决策轨迹、成交后的结果、全部存续持仓的退出与利润保护状态 |
| `/suggestions` LLM 建议 | 研究排名、逻辑、观察及失效条件、资料缺口 | 建议是否转成交易、排名是否生效、未采用原因、后续贡献 |
| `/api/llm/*` | 决策列表/详情、重放、部分角色指标、权限与健康接口 | 尚无对应完整分析页面；现有指标接口只列 selection/entry/position，不能直接假设覆盖全部角色和独立实验 |
| 研究报告与实验账本 | 策略比较、R/L 账户、应用事件、成本与结算记录等 | 统一入口、可比性说明、跨版本身份、可下钻的结果与等待原因 |

确认台已经展示“模型建议 / 当前有效动作”，应复用并补齐，不能把它描述成完全不存在。

### 2.1 当前状态必须分范围展示

- 主项目配置的 LLM 权限为 `shadow`，这描述的是该配置作用范围，不代表所有独立纸面实验。
- `L1-POSITION-20260922` 的启动记录显示：独立纸面 R/L 账户已启动，开放持仓 `hold/exit`，启动验收时没有评审对象、没有模型调用。
- 启动记录中的 24 个账户会话包含初始化回放，不能显示成 24 天真实 LLM 前向业绩。
- 文档记录不替代当前运行状态。页面上线后应读取对应实验的最新快照，并显示快照时间。

这一区分是核心需求：用户必须能看出“没有权限”“有纸面权限但暂无对象”“已经改变动作但结果未成熟”之间的差异。

## 3. 信息架构

在现有 Web 项目中增加分析页面，保留行情、确认台、LLM 建议的现有用途。不另建一套交易执行系统。

| 页面（建议地址） | 用户问题 | 主要展示 |
|---|---|---|
| 决策总览 `/overview` | 今天发生了什么，我需要做什么？ | 当前账户/实验、持仓与风险、机会流转、LLM 作用、待处理事项 |
| 持仓与退出 `/positions` | 为什么还持有，什么时候卖？ | 持仓表、保护状态、规则与模型分歧、退出时间线 |
| 买入机会 `/opportunities` | 为什么买或没有买？ | 候选漏斗、触发条件、淘汰原因、容量分配 |
| LLM 决策与贡献 `/llm-impact` | 模型到底做了什么，值不值得？ | 角色权限、建议到执行、R/L 对照、失误与收益案例 |
| 策略与实验 `/experiments` | 哪个策略值得保留，何时能判断？ | 买卖策略比较、实验进度、判定与风险权衡 |
| 决策详情 `/decisions/<id>` | 这一笔的完整来龙去脉是什么？ | 冻结输入→规则→模型→程序裁决→订单/纸面成交→结果 |

决策详情是共享下钻页面；不要求用户通过多层菜单寻找同一笔交易。

## 4. 全局上下文与页面规则

每页固定显示：运行范围（真实/模拟/纸面/历史研究）、账户或实验、策略版本、数据截止时间、最近成功更新时间。切换范围时所有卡片和图表一起更新。

- 默认总览可以列出多个范围，但各范围独立成卡，不合计真实与纸面净值。
- 实验使用显式来源登记，绑定 experiment_id、运行目录、manifest、账本/报告路径、schema 与导出版本；不按“最新文件”猜当前实验。
- 日期区分交易会话日、数据观测时间、决策时间、计划执行时间、实际成交时间。
- 时间以北京时间显示，可查看美东时间；交易日与截止时间按交易所日历和时区计算，不写死夏令时换算。
- 所有统计带起止日期、样本数、成本范围、估值口径和成熟状态。
- 主视图用中文解释；原始 ID、JSON、哈希、错误堆栈放在“证据与诊断”折叠区。
- 颜色同时配文字，不能只靠红绿区别盈利、风险与未成熟。

## 5. 页面需求

### 5.1 决策总览：先呈现结论与需要处理的事情

首屏从上到下：

1. **当前状态**：所选账户/实验、当前策略、实际可执行的 LLM 权限、数据是否就绪。
2. **需要处理**：待确认交易、执行结果待对账、数据阻断、预算耗尽等；注明影响和已有处理入口。没有待办明确显示“当前无需处理”。
3. **账户摘要**：净值、已实现/未实现损益、现金占比、持仓数量、最大回撤；缺少可信数据时不填估算值。
4. **本期交易与模型作用**：机会数、成交数、未成交主要原因、有效模型评审数、实际改变动作数、结果成熟数。
5. **正在验证什么**：当前买入、卖出与 LLM 实验各一行，列结论状态、阻碍/等待原因和下一评估条件。

示意布局（不是实际运行数据）：

```text
[范围/账户/实验] [统计区间] [数据截至 / 更新状态]
当前策略：…   LLM：仅记录 / 纸面执行 / …
需要处理：…（或当前无需处理）
[净值] [扣费损益] [回撤] [现金与持仓]
[买入机会与未成交原因]   [持仓退出与模型分歧]
[策略实验进度]           [LLM 贡献：可判断 / 尚未测得]
```

必须区分“作业成功运行”与“成功完成有效决策”。空仓且无机会时，可以显示“运行正常，暂无评审对象”。

### 5.2 持仓与退出：本轮最高优先级

每笔持仓展示：证券、策略、入场日期/价格、数量、当前价与时间、持仓会话数、浮盈亏金额及百分比、初始风险 R、当前收益 R、持仓期最大浮盈、浮盈回吐。

保护与退出区展示：

- 初始止损、当前已生效保护线、待生效保护线与生效日。
- 当前价到保护线的距离；注明保护线不保证跳空时的成交价格。
- 时间退出安排、其他退出触发条件，以及已满足/未满足/数据不足状态。
- 规则当前动作、模型最新有效建议、程序最终动作、未采用模型建议的原因。
- 最新评审时间、下次计划评审、当次可用信息与关键缺失。

单笔详情使用价格图叠加入场、已生效保护线和实际退出标记。待生效保护线用不同样式，不能提前画成已生效。模型评审标记可点击查看当时输入，历史位置不引用今天才知道的信息。

浮盈回吐默认使用持仓期最大收益率减当前收益率（百分点），同时显示锚点和价格/分红口径。若显示金额，需有数量及现金流一致的计算；减仓、拆股后不能简单用当前数量回乘历史峰值。数据不足显示“不可计算”。

排序提供：最近退出触发、回吐较大、数据过期、模型与规则分歧；不把排序结果包装成新的交易信号。

### 5.3 买入机会：看见没有成交的机会

展示从候选到成交的流程：

`候选 → 数据与资格检查 → 策略触发 → 评审（如适用）→ 资金/容量分配 → 交易提案 → 成交或终态`

每一层可展开证券、策略版本、当时条件、下一步所需条件，以及停留或终止原因。

- 区分没有信号、规则淘汰、模型否决、模型无执行权、容量不足、重复持仓、人工拒绝、过期、执行失败。
- 抄底机会显示观察/触发/失效/过期状态、趋势资格、回撤程度、恢复确认、最早执行时间；观察不等于可买入。
- 同时呈现规则排序与模型排序，并注明最终采用哪种排序。
- 容量冲突仅在有真实分配记录时显示“该机会被另一机会占用”；不能从两套策略成交集合不同推导挤占。
- “距触发还差什么”读取明确条件；不能凭评分差臆造成功概率。

没有保存历史淘汰信息的环节标“该阶段未采集”，不能把未采集对象记为零。阶段人数去重规则固定，同一对象的重试不新增机会。

### 5.4 LLM 决策与贡献：分开看参与、执行和结果

页面上半部按 selection、entry、portfolio、position、review 分角色展示：是否启用、当前作用范围、允许动作、实际权限、最近有效评审与数据覆盖范围。主链与 L1 分行。

中部使用决策清单，每条固定包含：

| 原规则动作 | 模型建议 | 程序生效动作 | 最终成交/应用结果 | 差异原因 | 结果成熟状态 |
|---|---|---|---|---|---|
| 继续持有 | 提前退出 | 沿用规则 | 未因模型卖出 | 仅记录建议 | 不计实际执行贡献 |
| 继续持有 | 提前退出 | 纸面退出 | 待下一会话执行 | 纸面权限通过 | 等待执行 |

上表是语义示例，不作为样本数据。

参与漏斗必须分别统计：应评审对象、输入就绪对象、实际调用、按期有效输出、可应用动作、已冻结应用、真正改变执行、结果成熟。有效 HOLD 与规则一致应单列，不能归为失败，也不能算成改变动作。

不执行/弃权至少区分：主动弃权、证据不足、权限未开放、预算阻断、超时、无效输出、超过截止、硬退出优先、执行未兑现。调用成功但输出无效不计有效评审。

下半部展示：

- 同一实验 R（规则）和 L（规则＋LLM）的净值与回撤，另画 L−R 差值。
- 扣费收益差、最大回撤差、暴露差、成交数、胜率与盈亏比，并列成熟样本量。
- 模型已知费用、费用未知次数、在途预留、预算占用与剩余可用预算。
- 最有帮助与最有损害的决策都可下钻，包括退出后避免的损失、错过的上涨；固定观察期限，不能事后挑有利期限。

无实际干预样本时显示“尚未测得模型执行贡献”。即使两条净值线重合，也应注明零干预、有效维持原计划或样本未成熟，不能直接判定模型无效。

### 5.5 策略与实验：解释结论，不只列收益榜

按买入、卖出、LLM 三类组织，默认优先展示正在运行与最近完成的实验，失败与防守性结果保留可见。

每个实验显示：假设、父策略、唯一或明确列出的差异、股票池、风险预算、交易成本、历史探索/真实前向性质、起止时间、版本、登记条件、实际进度、判定与下一动作。

对比指标：扣费收益、胜率、平均盈亏比、最大回撤、尾部风险、暴露、换手、成交数与未完成交易。注明账户级或同机会级结果，不能混成排行榜。

- 胜率提升但净收益下降，直接显示两者的权衡。
- 风险改善但收益下降，显示“防守性权衡”，不显示“全面优胜”。
- 仅历史探索结果不能显示为已获前向验证。
- 进度展示实际条件，例如评估日期与成熟样本要求分别满足多少；不把重复决策次数当独立样本，不用简单百分比推测完成日。
- 初始回放、正式前向开始、首次真实模型评审分别标记。
- 文档判定与机读结果冲突时显示“结论待核对”，保留原始来源，不让模型自动润色成一致结论。

### 5.6 决策详情：可核对的完整轨迹

时间线按实际发生顺序展开：冻结数据、规则计划、模型输入、模型输出、校验/权限裁决、人工操作（如有）、订单或纸面执行、结果结算。

每一段显示时间、动作与证据来源。输入引用可定位到真实技术事实或资料片段；模型推断与程序计算事实明确区分。模型没有报告的理由不由页面另调模型补造。

用稳定 ID 关联机会、持仓生命周期、decision、application、订单及成交；证券代码相同不代表同一笔交易。关联缺失时显示断点，不能按股票和近似时间拼出貌似完整的轨迹。

## 6. 数据来源与接入边界

以下是已有读取能力与拟新增工作，接口地址不代表已经实现。

| 信息 | 已有来源 | 还需完成 |
|---|---|---|
| 确认提案、模型建议、计划 | `web/app.py` 的 approvals 接口与现有模板 | 关联成交、决策详情及账户范围 |
| 主链决策、权限与健康 | `/api/llm/decisions`、详情、metrics、permissions、health | 统一状态语义、分页/筛选、补足角色覆盖与配置读取失败标识 |
| 持仓与硬退出 | `position_registry.py`、退出与执行事件 | 只读持仓投影、保护线生效时序、历史回吐字段可用性核验 |
| 纸面 R/L、模型应用与结果 | `scripts/portfolio_shadow/report.py` 及对应实验账本 | 显式实验来源、独立版本导出、真实前向区间和成本展示 |
| 策略比较 | `scripts/strategy_research/report.py` 及研究结果文件 | 结果摘要适配、版本与登记绑定、机读结论一致性检查 |
| 作业与等待原因 | `ops/shadow_status.py`、既有运行记录与监控 | 汇总业务影响；不另建调度系统 |
| 历史漏斗、退出后表现 | 既有诊断/结算能力，覆盖需逐项确认 | 缺字段时增加只读离线投影；无历史记录则明确缺失 |

L1 与主 checkout 存在账本 schema 差异。优先由各自固定运行版本提供只读导出，Web 消费统一快照；不得用主项目 ORM 强开不兼容账本或为了页面升级实验 schema。

建议新增只读查询：overview、positions、opportunities、experiments、paper-impact。正式路径与字段在开发时定稿，复用现有接口，避免复制同一指标算法。

统一响应至少包含：`scope_id`、`account_id/experiment_id`、`strategy_version`、`as_of`、`generated_at`、`source_ref`、`data_status`、`missing_reasons`。指标附 `value`、`unit`、`sample_count`、`window`、`cost_basis` 与成熟状态。

页面访问只读取快照或只读查询，不触发付费模型、补跑决策、重结算或交易。现有 replay API 是否有写入行为需另行审查，不能仅凭 GET 名称接到自动刷新。

## 7. 指标与缺失语义

| 指标 | 展示约定 |
|---|---|
| 扣费收益 | 说明已扣哪些交易/模型费用；未知费用单列，不称为完整全成本结果 |
| L−R 收益差 | 相同实验、起点、资金及区间下收益率之差，单位为百分点；金额差另外列 |
| 胜率 | 盈利已平仓交易数 / 有结果的已平仓交易数；保本计入分母，未平仓另列 |
| 平均盈亏比 | 平均盈利金额 / 平均亏损绝对金额；无亏损或样本不足明确状态，不填 0 |
| 最大回撤 | 同频率账户净值的峰谷跌幅，显示取样频率与区间 |
| 尾部风险 | 复用实验登记的定义，注明日收益 ES 或单笔损失口径，不跨口径直接排名 |
| 模型实际改变率 | 改变执行的去重决策数 / 具备应用资格的有效决策数；分子分母可下钻 |
| 有效覆盖率 | 按期有效评审 / 应评审对象；同时列出数据阻断和不可调用对象，标清现有报告口径差异 |
| 成熟样本 | 按实验登记的独立单位统计，不能用多日重复评审数代替 |

正式实现应为现有指标定义建立版本映射。上表与已有登记不一致时，展示登记口径并清楚命名，不静默改写已冻结实验的统计方式。

统一状态：有效数值、暂无对象、等待执行、等待结算、样本不足、未采集、数据过期、读取失败、不适用。只有真实计算得到的零才显示 `0`；空值不自动转零。

不使用未经校准的“买入成功率”“LLM 胜率预测”。模型自报信心只能标为模型自报，不能当历史命中率。

## 8. 交付顺序

### 第一批：先看清当前在发生什么

- 总览、持仓与退出、共享决策详情。
- LLM 页面先交付建议/生效/成交差异与范围权限；已有 R/L 数据可展示，缺失明确说明。
- 同期提供简洁的买入机会表和实验状态清单，保证买入方向与实验等待原因可见。
- 首批结束时，用户能从总览进入一笔持仓，解释为什么持有、什么条件卖、模型是否改变动作，以及当前数据是否可信。

### 第二批：看清策略和 LLM 是否有效

- 完整 R/L 贡献、成本预算、提前退出的收益与损害案例。
- 策略实验对比、风险权衡、成熟条件与结果来源。
- 买入漏斗细化至未成交原因、容量分配和抄底状态。

### 第三批：改善日常使用

- 保存常用筛选、跨页面状态保留、对照导出、移动端可读性。
- 仅在前两批确有使用需求后增加进一步图表，不以图表数量衡量交付。

## 9. 验收场景

1. 主链给出 EXIT 但权限为 shadow：页面明确显示未因模型退出，不能显示“已卖出”。
2. L1 给出有效 EXIT 且未到执行时间：显示纸面退出待执行，成交后再转已兑现。
3. 没有持仓与评审对象：显示正常等待，贡献尚未测得，不显示故障或零胜率。
4. 超时且成本未知：分别显示调用失败和未知费用占用，不显示零成本。
5. 规则硬退出覆盖模型 HOLD：解释覆盖原因，原模型意见仍可查看。
6. 数据过期：净值与行情显示真实数据时间，不因网页刚刷新而显示“实时”。
7. 初始化回放有净值但无真实模型决策：回放区间与前向区间分开，不能用于扩大模型有效样本。
8. 策略胜率上升但收益下降：两个变化同时可见，页面不生成“策略提升”的误导结论。
9. 多账户或不同实验同一股票：切换范围后数据不串联，同证券再入场也不继承上笔轨迹。
10. 来源读取失败或 schema 不兼容：显示不可用与具体来源，其他卡片仍可使用，不返回伪造的空账户。
11. 盈利和亏损案例都可访问，筛选不改变冻结实验的正式结论。
12. 打开、刷新、筛选页面不会调用模型、修改账本、触发订单或改变实验配置。

首批验收使用至少一条可用的真实轨迹核对来源；尚无真实样本的状态用明确标识的测试数据验证，不能混进业务统计。图表与表格的同一指标必须一致。
