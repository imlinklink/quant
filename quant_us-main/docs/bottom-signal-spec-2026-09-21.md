# 买入侧第二批规范：趋势回撤型抄底信号（可直接进入实现）

日期：2026-09-21。上位规划：`docs/next-system-implementation-plan-2026-09-21.md` §5、§7、§8、§10.7。
状态：**实现规范**，不是试验预登记，不表示参数已验证。正式试验的预登记在开算前另立
（照第一批 `EXIT-PROTECT-20260921` 的做法：先写机读登记与门槛、再计算）。

## 1. 产品定义（第一版刻意窄）

**「抄底」限定为「上升趋势中的回撤企稳」**，不尝试识别熊市最低点，也不给未经校准的
「成功概率」。它是一条**独立买入变体**，与 B3 对照；**不默认叠加进生产交易**。

## 2. 状态机

```
INELIGIBLE ──(趋势条件成立)──> WATCH ──(价格恢复确认)──> TRIGGERED ──(T+1 开盘)──> 成交 / 账户拒绝
                                │                                                    │
                                ├──(超过等待窗)────> EXPIRED                          └──> 进入常规持有/退出规则
                                └──(趋势破坏 / 风险距离过大 / 关键数据缺失)──> INVALIDATED
```

**信号的成败与账户的结果分开记**：`TRIGGERED` 之后的成交、账户拒绝（容量/现金）、数据阻塞
单独记录，**不得**混成「信号成功/失败」。

## 3. 逐条定义（阈值在此固定；实现时不得在看结果后改）

| 项 | 定义 | 理由 |
|---|---|---|
| 资格 | 沿用同一股票池与质量要求（`verified` 区间）、可交易性；要求 `ATR14` 有效 | 池子与质量不属本轮变量 |
| 长期趋势 | `close > MA200` **且** `MA200(t) > MA200(t−20)` | 用两个明确的不等式定义「上升」，不做斜率拟合（避免新的自由参数） |
| 回撤深度 | 从**过去 252 个 session 内已完成收盘价的高点**回撤 ≥ `max(3.0 × ATR14, 10% × 高点)`；见下方「口径精确化」 | 与既有止损同一口径（ATR 与百分比取宽者）；防「小幅回调也算抄底」 |
| 进入 WATCH | 上述两条同时成立的那一天，记 `watch_session` | 状态身份固定，事后不重解释 |
| 确认（只选一种） | **在本次 WATCH 期内，收盘价首次回到 MA20 之上**（前一日收盘 ≤ MA20） | 单一、可检验、不可事后合成的「企稳」确认。均线回收与前日高点突破**不叠加** |
| 执行时序 | T 收盘确认 → **T+1 开盘**执行 | 与 B3 一致；不假定能按确认价成交 |
| 等待窗 | WATCH 起 **20 个 session** 内未确认 ⇒ `EXPIRED` | 沿用冻结 B3 的 `max_wait_sessions`（H-B 是另一个假设，不在本轮重开） |
| 失效 | 趋势破坏（`close < MA200` 或 MA200 转下行）／初始止损距离 > **25% × 入场价**／ATR 无效或价格缺口 ⇒ `INVALIDATED` | 「超出风险距离」有明确数值边界，不靠感觉 |
| 冷却期 | `EXPIRED` / `INVALIDATED` 之后 **20 个 session** 内该证券不再进入 WATCH | 防同一个下跌反复触发、制造虚假样本量 |
| 再入场 | 已 `TRIGGERED` 而未成交（容量/现金拒绝）⇒ 记 `UNFILLED`，**不自动重试、不回填更漂亮的入场价** | 不把「没买上」改写成「买到了更好的价」 |
| 重复持仓 | 沿用账户既有规则（`DUPLICATE_ACTIVE_SECURITY`） | 不是本轮的变量 |

**这个包替换的是 B3 的整个入场包**（月排名 + 市场门 + 周线 + 日线择时），**不是「移除了日线过滤」**
（那是 H-A，结论 CONCENTRATED，**不重开**）。保留不变：股票池、质量要求、H60 期限退出、
初始硬止损公式 `max(8% × 入场价, 2.5 × ATR14)`、单笔风险预算、五仓上限、费用与公司行动会计。
**市场门本期不沿用** —— 因为整包被替换；这一点必须写进试验 manifest，且结论只能表述为
「新入场策略 vs B3」，不能表述为「B3 少了一道过滤」。

**触发频率不设目标**：实测出来是多少就报多少，不为凑数调阈值（§9 明令不按日历承诺收益验证）。

### 口径精确化（实现时撞到、在此写死）

1. **回撤两侧都相对「当前收盘价」**，不是相对高点：
   `(high_lookback − close) / close ≥ max(3 × asof_atr / raw_close, 10%)`。
   原因是基准一致性：左侧是**复权序列**的比值（与基准无关），右侧是面板里同一 session 的
   原始价比值。若写成「相对高点」，右侧的 ATR 项就与左侧不同基，在复权因子大的地方会算出
   废话（实测把「复权价 + 原始 ATR」混用会让止损算出**非正距离**并抛
   `INITIAL_STOP_NON_POSITIVE`）。代价是 10% 这一档实际是「低于高点 9.09%」而不是 10%
   —— 定义以本行为准，不以直觉为准。
2. **同日冲突里只有两条真正可达**：`ATR 无效` 与 `等待窗过期`。
   「趋势破坏 vs 收回 MA20」在同一 session **不可能同时成立** —— 进 WATCH 的前提就是趋势成立
   （`close > MA200` 且 MA200 上行），而反弹日的收盘仍在 MA200 之上。代码保留完整优先级
   （作为防御性约定），但测试只对可达的两条设断言；把不可达的那条写成测试会得到一条恒真的
   断言（实测：把回收检查提到趋势检查之前，那条测试照样全绿）。

## 4. 用户可见输出与记录

每个信号一行，含：证券、候选轮次、状态、数据截止时间、回撤深度（% 与 ATR 倍数）、趋势条件与
企稳条件的取值、`watch_session`、信号日、最早执行日、初始风险距离、失效/过期原因、规则版本。
观察名单（WATCH）与可执行买入意图（TRIGGERED 排期）**分开展示**。

## 5. 试验口径（实现完成后、开算前写进预登记）

- **两臂**：A = B3（原入场 + 原退出）；B = 本信号入场 + **同一套原退出规则**（不把第一批的新退出
  接进来 —— 那一批的结论是保留原退出）。
- **共用**：同一数据、日历、成本、账户风险限制、同空仓起点、同引擎。
- **报告必须含**：共同机会、新增机会、B3 独有机会、账户拒绝机会；**同时呈现新增盈利与新增亏损**
  （只报新增盈利就是把"多买了一些"读成"策略更好"）；候选截止日**只按共同可观察期限**决定，
  不按最终是否提前止损挑样本；披露两侧信号密度不同，**不强行把不对应的交易配成对**。
- **主目标**：全成本账户收益改善。**必须同时报告并被预登记约束**：胜率、盈亏比、MDD、尾部风险。
- **建议门槛**（形式化时定稿，数值照第一批的口径）：账户级终值收益差 > 0；`abs(MDD差) ≤ 0.03`；
  尾部不劣于基线；单一证券贡献 ≤ 50% 且 leave-one-out 仍为正；2× 成本下仍为正。
- **窗口性质**：历史窗口已被查看过，只作探索与淘汰；正式资格需另立前向登记。
- 机会级的 MAE、触发后失效率用于**解释**，不替代账户结果。

## 6. 实现前置（两条已核实的现成件，不要另造）

1. **均线与回撤高点必须取自复权序列**，不能取自原始价。仓库里已有这条路径：
   `timed_entries._adjusted_bars(bars, actions, as_of)`（内部 `build_price_view(price_basis='asof_adjusted')`），
   现有周线/日线信号用的就是它。用原始价会让拆股处出现**假趋势破坏**——本池子里
   NVDA 4:1 与 10:1、AMZN 20:1、GOOGL 20:1、AAPL 4:1 都在窗口内。
2. **冻结面板里没有证券级 `asof_close` / MA 列**（只有 `raw_*`、`volume`、`asof_atr`、`scale_to_next`）。
   所以 MA200/MA20 要在研究层从冻结的原始价**算**出来，**不要**去改面板构建器 ——
   面板列一变，冻结 study 的输入哈希就对不上，对账（VERIFIED）也就无从谈起。

顺带一条已经证明过的性质（P0-4，`docs/交付总结-2026-09-20.md`）：这些条件全部是**比较型**
（`close > MA200`、`MA200(t) > MA200(t−20)`、`回撤 ≥ max(3×ATR, 10%×高点)`），
未来公司行动对整个回看窗施加**同一乘法因子**而抵消，所以 `as_of` 取「窗口最后一天」与
「逐决策日」等价。这也是可以照 `precompute_signals` 那样预计算的理由。
