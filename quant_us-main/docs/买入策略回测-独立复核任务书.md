## 1. 背景：两条买入线是什么

### 1.1 dip_buy —— 15 分钟日内均值回归

- **入场**：`mutifactor/utils/intraday_scoring.py::analyze_score()`，评分 0–10
  （超卖 0-3 + 布林 0-2 + 成交量 0-2 + 真实背离 0-3，再叠加趋势调整 -3~0），
  `adj_total >= buy_threshold(7)` 触发；弱趋势下 `raw >= 7` 可绕过阈值。
- **入场时点**：信号 bar 收盘后，**下一根 bar 开盘**买入。
- **出场**：`mutifactor/strategies/dual_chandelier.py::PositionExitState`，
  参数取 `config.yaml → chandelier.profiles.dip_buy`（-5% 固定 / +2% 移保本 / +4% 激活移动止盈），
  外加 `dip_buy.time_exit_bars = 8` 根（= 2 小时）时间出场。
- **风控**：单笔 $5,000、最多 3 个持仓、单股单仓、冷却 30 分钟。
- **实盘还有 6 个门**（回测**未**复现，见 §5.3）：`index_gate` / `reversal_gate` / `rr_gate` /
  `earnings_gate` / `daily_trend_gate` / 60m 环境门。

### 1.2 donchian —— 日线趋势跟踪

- **入场**：收盘价突破**此前 N 日**最高价（不含当日），**次日开盘**买入。
- **出场**：2×ATR(14) 吊灯 + 5% 保底。
- **变体**：N=20/55，可选放量 1.5× 过滤、站上 MA50 过滤。

## 3. 待验证的 7 条结论

> 每条都给出了**原始数字**与**证伪条件**。请独立复算。

**C1｜dip_buy 入场信号零边际。**
4,328 笔时间出场（TIME_EXIT）的**毛**胜率 49.0%、毛均值 **+0.026%**、中位 0.000%。
→ 证伪条件：用独立实现算出毛胜率显著偏离 50%（例如 <47% 或 >53%），或毛均值显著非零。
→ 注意：这里的「零」是**统计上无法区分于零**，不是「略负」。请给出置信区间。

**C2｜即使零成本，dip_buy 也是负期望。**
毛总收益 **-$41,967**，成本合计约 $48,730。即亏损不只来自成本。
→ 证伪条件：算出毛总收益为正。

**C3｜亏损集中在止损单。**
545 笔 STOP_LOSS 均值 **-1.75%**（不是 -5%），合计约 -$47,600；
而 4,328 笔 TIME_EXIT 毛收益合计约 **+$5,600**。
→ 证伪条件：给出不同的归因拆分。

**C4｜出场参数与持仓周期严重错配。**（最值得复核的一条）
中位持仓 **0.073 天**（≈1.75 小时 = 7 根 15M bar），而括号是 -5%/+2%/+4%、时间出场 8 根。
→ 请独立验证：**在 1.75 小时的持仓窗口内，-5% 止损和 +4% 移动止盈的触发概率分别是多少？**
如果两者都接近 0，则 89% 的交易「原价出场」是数学必然，不是策略行为。
→ 这是判断「策略无效」还是「参数错配」的关键。两者含义完全不同。

**C5｜donchian 参数不敏感，但参数优化无样本外价值。**
前进分析 6 折平均 **IC = -0.03**；最优格战胜中位比例 **3/6（=50%）**；
每年重选参数的「前进组合」($16,277) **反而差于**固定 55/2.0 ($20,796)。
→ 证伪条件：算出的平均 IC 显著 > 0。

**C6｜donchian 收益高度集中在 2025–2026。**
分年中位期望：2021 ≈ -91、2023 ≈ -44、2024 ≈ -39，而 2025 ≈ +942、2026 ≈ +666。
→ 请独立核算：**去掉 2025–2026 后，总收益是多少？** 是否为正。

**C7｜简单均线 regime 过滤无效。**
指数 MA50/100/200 与个股 MA50/100/200 六个变体，30 个「配置×年」格子中仅 3 个改善；
且个股>MA50 与基线**逐笔完全相同**（因为「收盘突破 55 日高点」蕴含「已在 50 日均线上方」）。
→ 请验证最后这条逻辑推理是否成立（这是个纯数学命题，不依赖数据）。

## 4. 你还需要**主动**检查的东西（本文未覆盖）

这几项我们没有系统检查，**可能是最容易被忽略的重大缺陷**：

**4.1 幸存者偏差。** 观察池是 `config.yaml → dip_buy.watch_list` 的 8 只票
（SNDK/MU/SOXL/YINN/LITE/AXTI/RAM/MULL）。**请判断：这个池子是不是事后选的？**
如果是用「后来涨得好的票」组出来的，则两条策略的回测结果都严重高估。
检验方法：看这些票的上市时间、纳入时间；或用**同期全市场随机抽样**做对照。

**4.2 前视（look-ahead）。** 逐 bar 检查每一项输入是否只用了「当时已知」的信息。
重点：`analyze_score` 的 rolling 窗口、`add_indicators` 的 `shift(1)`、ATR 的可用时点、
入场是否真的用「下一根开盘」。项目里虽有测试（`test_*` 里有无前视用例），
**但请独立构造验证，不要相信测试本身**。

**4.3 成本模型是否低估。** 回测用 **0.20% 往返**。但 MULL/RAM/AXTI/LITE 是小盘股，
真实价差+滑点可能远高于此。请给出**成本敏感性**：成本取 0.1% / 0.2% / 0.5% / 1.0% 时，
dip_buy 与 donchian 的期望分别怎么变。**dip_buy 对成本极度敏感是它的核心脆弱点。**

**4.4 分段拼接是否漏交易。** dip_buy 的 4,873 笔由**两个 60,000 根窗口**拼接而成
（2021-01 起 + 2024-03 起，`--append` 去重）。请检查**接缝处是否有缺口**
（例如 2024 年某段的笔数是否异常少）。

**4.5 出场引擎调用是否正确。** 我们注意到实盘 ATR 用的是 **60 分钟** bar
（`chandelier_exit_manager` 的 `atr_cache`），回测已改为从 15M 重采样出 60M。
**请核对这个转换是否正确**，以及 `PositionExitState.recompute(atr, price)` 的
`atr` 量纲（绝对价格 vs 比率）是否传对。

**4.6 统计显著性。** 所有结论都建立在「样本」上。请对被引用为证据的关键数字
（尤其 C1 的 49.0%、C3 的 -1.75%、C6 的分年数字）给出**置信区间或 bootstrap 检验**。
区分「数字不同」与「统计上不同」。

## 5. 已知陷阱（我们踩过，请避免重复）

**5.1 静默截断——最危险的一个。**
富途限流时 API 报错，早期实现把错误当成「没有更多数据」正常收尾，
**导致数据被静默截断而报告看起来正常**。曾出现「8 只票里 6 只返回空」
但覆盖表仍显示 OK 的情况。现已改为标记 `truncated` 并拒绝出结论。
→ **你复核时务必先确认数据完整性**：每只票的起止日期和 bar 数是否合理。
→ 次新股（SNDK/RAM/MULL）天然只有上市后数据，区间短是正常的；
但 **MU/SOXL/YINN/LITE/AXTI 必须覆盖到 2021 年初**，够不到就是被截断。

**5.2 零填充造假相关。**
组合分析曾用 `resample('MS').sum()` 直接对齐，没交易的月份被填成 0，
算出的「相关性 0.16」是零填充的产物，不是真互补。现已改为只在**双方都有交易**的月份上算。
→ 你做任何时间对齐/相关性分析时，先确认「缺失」是缺失还是零。

**5.3 未复现的门会让结论被误读。**
回测**没有**实现 `index_gate`/`reversal_gate`/`rr_gate`/`earnings_gate`/`daily_trend_gate`，
所以笔数**多于实盘**。
→ 注意：期望为负时，「笔数更多」**不构成**对实盘有利的偏差。不要说「实盘会更少所以更好」。
→ 正确的说法是：这些门是质量筛选，**能否把 49% 的胜率推到有意义的正期望，需要逐门实测**——
举证责任在门这一方。打平 0.2% 成本需要毛均值从 -0.172% 提到 **+0.20%**。

**5.4 不要在同一段历史上挑参数。** 见 C5 —— IC≈0 说明「用历史挑参数」本身无信息量。

**5.5 小心「跑通≠正确」。** 项目里的单元测试覆盖了无前视、分页、闸门等，
但**测试通过不代表回测正确**（测试可能测错了东西）。请独立构造验证。

## 7. 判定标准：什么算「证实 / 证伪」

| 判定 | 要求 |
|---|---|
| **证实** | 用独立实现或独立数据复算出同量级结果，**且给出统计不确定性** |
| **证伪** | 给出**具体反例**或**量化差异**（不是「我觉得不对」） |
| **证据不足** | 明确说明缺什么数据/方法，以及**需要什么才能判定** |

**对每条结论，请至少给一个「如果这条是错的，会最先在哪里露馅」的判断。**
