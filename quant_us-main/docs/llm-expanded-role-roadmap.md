# LLM 深度参与选股、买入与卖出的下一阶段规划

更新时间：2026-09-08。适用基线：任务 A–E 及其审查修复完成后的 quant_us-main。

## 目标与原则

目标不是让 LLM 直接接管交易，而是让它在三个最需要语义判断的环节产生可测量的增量价值：

1. 从可交易股票池中发现和排序更值得研究的股票；
2. 对规则已生成的买入候选判断“现在是否值得执行”；
3. 持仓期间识别投资逻辑变化，帮助决定继续持有、提前退出或按原计划退出。

程序继续独占以下权力：账户选择、数量计算、总风险和行业风险上限、价格时效、订单幂等、止损底线、成交对账和数据库事务。LLM 不生成最终订单参数，也不能放宽程序保护。这样可以扩大 LLM 的决策作用，同时让每次影响都可归因、可回放、可撤销。

## 建议的目标架构

```text
市场与事件数据
      │
      ▼
确定性数据质量检查 ──► 不合格数据隔离
      │
      ▼
LLM 选股研究员：主题发现、催化剂/风险、候选排序
      │  只输出候选与证据，不下单
      ▼
现有策略规则：抄底、突破、回踩、风险资格
      │
      ▼
LLM 入场评审员：执行 / 暂缓 / 反对，给出失效条件
      │
      ▼
人工批准 + 程序风控 + 券商执行
      │
      ▼
LLM 持仓评审员：逻辑增强 / 不变 / 减弱 / 失效
      │
      ▼
退出建议：持有 / 提前退出 / 按保护线退出
      │
      ▼
人工批准 + 程序止损底线 + 券商执行
```

三个 LLM 角色必须使用独立 prompt_version、schema_version 和评估指标。不要把选股、买入和卖出塞进一次对话，也不要让前一个角色的自然语言结论成为后一个角色未经核实的事实。

## 阶段 F：建立统一、可追溯的研究输入

这是扩大 LLM 作用前最重要的一步。模型的上限首先取决于它看到的数据，而不是提示词长度。

### F1. 建立 Evidence Packet

为每只股票、每个决策时点生成冻结的 `evidence_packet`，至少包含：

| 数据组 | 必需字段 |
| --- | --- |
| 身份 | code、公司名、行业、风险组、决策时点、市场状态 |
| 行情 | 最新价格及时间、1/5/20 日收益、成交量相对值、ATR、趋势和关键价位 |
| 策略 | 各策略是否通过、原始分数、未通过原因、入场价、初始止损、目标和收益风险比 |
| 事件 | 财报、指引、公告、分析师变化、行业/宏观事件；来源、发布时间、取得时间、独立事件簇 |
| 基本面 | 最近财报期、收入/利润变化、估值字段及数据日期；缺失必须显式标记 |
| 账户约束 | 是否已有持仓、行业风险占用、持仓数量上限；不提供账号、现金绝对值和密钥 |
| 数据质量 | 缺失项、陈旧项、冲突项、未来时间、来源等级 |

每个事实都有 `evidence_id`、`source`、`published_at`、`observed_at`、`content_hash`。指标由程序计算，LLM 只解释，不自行重新计算价格、ATR、仓位或盈亏。

建议新增：

- `scripts/live_trading/decision_ledger/evidence_packet.py`
- `scripts/live_trading/data_quality.py`
- `tests/unit/live/test_evidence_packet.py`

验收标准：同一决策时点输入可复现；缺失和过期数据不会被写成正常值；重复媒体报道聚合到同一事件簇；任何 LLM 事实都能回到输入证据。

### F2. 先统计缺口，再接数据源

用现有 `input_quality.py` 统计 2–4 周真实扫描中最常见的资料缺口。按出现频率和决策影响补数据，避免一次接入大量低价值新闻。第一批建议优先：行情时间、财报/指引、公司公告、行业重大事件和下一财报日期。

`register_material_event` 应接收已经过规则确认的重大事件。事件分类、去重和时间校验由程序完成；LLM 可以解释影响，但不能自行把一条新闻升级为“重大事件”并撤销批准。

## 阶段 G：让 LLM 真正参与选股

当前建议池更像报告摘要。下一步应把它升级为“研究候选生成器”，与策略扫描形成互补。

### G1. 两段式选股

第一段由程序每天生成可交易基础池：价格、流动性、数据完整性、可交易状态、黑名单、财报风险和组合集中度均满足要求。第二段由 LLM 在这个池内完成：

- 识别当前市场主题和催化剂；
- 将候选按 1–3 个预先定义的时间周期排序；
- 给出支持证据、反对证据、主要缺口和观察条件；
- 判断最适合的策略入口，例如“等待回踩”“只在突破确认后考虑”；
- 输出最多 N 只候选，允许输出空列表。

LLM 不得凭空加入基础池之外的代码。若希望模型发现新股票，建立单独的 `discovery_pool`：新代码先经过程序的数据和流动性资格检查，下一轮才能进入正式候选池。

### G2. 结构化输出

每只候选建议输出：

```json
{
  "code": "US.X",
  "rank": 1,
  "horizon": "1-5_sessions",
  "thesis": "...",
  "catalyst_evidence_ids": ["..."],
  "counterevidence_ids": ["..."],
  "preferred_entry_mode": "pullback",
  "watch_conditions": ["..."],
  "invalidators": ["..."],
  "confidence_bucket": "medium",
  "missing_information": ["..."]
}
```

`confidence_bucket` 只是排序特征，不是胜率，不参与仓位计算。

建议新增 `stock_research.py` 和 `selection_schema.py`，并将 `llm_suggestions` 的历史建议升级为版本化研究批次：`research_batch_id`、`universe_hash`、`as_of`、`prompt_version`、`model`、`input_snapshot_id`。

### G3. 如何评价选股价值

每天同时保存：完整基础池、LLM 前 N 名、规则扫描通过名单和未入选名单。用固定的 1/3/5/10 会话收益、MFE、MAE和是否触发策略入口评价排序，不能只评价最终人工买入的股票。

至少比较：

- A：基础规则排序；
- B：LLM 排序；
- C：LLM 排序后仍须规则触发；
- D：人工最终选择。

核心指标是横截面 rank IC、Top-N 相对基础池收益、下行尾部、覆盖率、换手率和资料不足率。选股阶段不使用最终账户收益作为唯一指标，因为账户约束和入场时机混在其中。

权限路线：先影子排序；达到样本门槛后允许 LLM 调整观察池优先级；最后才考虑让 LLM 推荐新增代码。它始终不能创建订单。

## 阶段 H：扩大 LLM 在买入决策中的作用

当前模型只对已生成计划作支持/暂缓/反对判断。可以把它发展为“入场质量评审员”，但仍在规则候选和程序风险边界内工作。

### H1. 入场评审应回答的五个问题

1. 当前信号是否与市场环境、行业状态和催化剂一致？
2. 这是抄底修复、趋势延续还是事件驱动，策略标签是否匹配？
3. 当前最强反对证据是什么，是否足以暂缓？
4. 哪个可观察条件会使计划失效或值得重新评审？
5. 资料是否足够支持执行？

输出继续使用 `support_execute / defer / oppose_execute`，增加稳定原因码，例如：`event_risk`、`regime_conflict`、`weak_confirmation`、`stale_evidence`、`poor_asymmetry`、`data_gap`。自然语言解释附属于原因码，不直接驱动程序。

### H2. 允许模型影响什么

第一阶段允许：

- 对合格候选排序；
- 支持、暂缓或反对执行；
- 建议更早复核的时间和条件；
- 建议在预先计算的计划模板中选择一种，例如“标准入场”或“等待确认”。

暂不允许：

- 自由生成股票数量、入场价或止损价；
- 将不合格信号改为合格；
- 提高单笔/组合/行业风险上限；
- 延长已经过期的审批；
- 因“信心高”增加仓位。

如果后续希望 LLM 影响仓位，只能在程序先算出的离散档位中选择，例如 `0 / 0.5x / 1.0x`，且 `1.0x` 是现有风险上限。先做影子记录，证明校准后再开放 `0.5x` 降档权；不开放加档权。

### H3. 加入反事实记录

每个候选无论最终是否批准，都冻结：规则计划、LLM 结果、人工动作、决策时可得行情，以及如果在统一执行假设下买入的后续结果。这样才能判断 defer/oppose 是否真的避开了亏损，而不是只观察被买入的样本。

至少积累 100 个规则通过候选、30 个可比较执行样本，并覆盖多种市场状态后，再讨论权限升级。数字是首轮工程门槛，不是统计显著性的保证；最终还要看置信区间和时间分块稳定性。

## 阶段 I：让 LLM 深度参与持仓与卖出

卖出阶段比买入更适合发挥 LLM 的事件理解能力，但必须区分硬退出和判断型退出。

### I1. 双层退出结构

**保护层**由程序执行：灾难止损、价格保护线、最大持有期、账户级风险事件。LLM 不得降低或取消保护线。模拟阶段可以保留人工确认，但生产设计应避免网络或模型故障使硬止损失效。

**判断层**由 LLM 参与：财报/公告改变逻辑、催化剂兑现、行业反转、价格行为与基本面背离、持有机会成本。模型可以建议 `hold / exit_early / tighten_review / thesis_invalidated`。

不要让“长期仍看好”成为忽略已触发保护线的理由；也不要让短期价格下跌本身自动成为基本面失效证据。

### I2. 持仓状态机

将现有 `position_review.py` 从影子事件扩展为版本化 thesis ledger：

```text
建立逻辑 → strengthened / unchanged / weakened → invalidated → closed
```

每次状态变化必须引用新增证据，并和上一版做 delta：新增了什么、撤销了什么、哪个失效条件被触发。没有新证据时，同一输入不应仅因模型措辞变化改变 thesis_state。

触发时点建议：

- 买入后首个收盘；
- 每个交易日收盘；
- 接近目标或保护线；
- 财报、指引和重大公告；
- 异常成交量或相对行业显著背离；
- 人工请求复核。

同一证据簇和同一价格窗口去重，避免行情抖动反复调用。

### I3. 卖出权限逐级开放

1. **影子期**：只记录建议，实际完全沿用当前退出流程。
2. **人工建议期**：LLM 可生成提前退出提案，必须人工批准；硬保护仍由程序约束。
3. **有限自动期**：只有 `thesis_invalidated` 且满足预先定义的程序条件时，允许自动降低风险，例如生成卖出提案并置顶，而非直接下单。
4. **自动执行评估期**：只有在足够样本证明延迟、故障降级和净收益改善后再单独设计；这不是当前阶段目标。

买入与卖出模型结果要分别评估。一个擅长新闻选股的模型不一定擅长退出时机。

## 阶段 J：模型评测、路由与权限治理

### J1. 离线模型评测集

从真实事件账本抽取脱敏、按时间冻结的案例，建立版本化 eval set。覆盖：优质/劣质候选、资料不足、冲突证据、财报前后、跳空、趋势反转、止损已触发、提示注入文本和数据陈旧。

每次更换模型或提示词先跑：schema 合格率、引用正确率、无依据事实率、动作一致性、重复运行稳定性、延迟、成本和安全规则违反率。只有评测通过才进入影子运行。

### J2. 多模型不应简单投票

如果使用多个模型，按任务路由：轻量模型做摘要/分类，强模型做最终评审；程序负责证据校验。不要用多数投票掩盖所有模型共享同一错误数据的问题。高影响决策可以采用“研究员提出、审稿员找反证”的双模型结构，两者输入和输出均落账本。

### J3. 权限升级门槛

每项 LLM 权限单独维护状态：`shadow → recommend → constrained_action → disabled`。升级前至少满足：

- 足够的独立样本和多个市场阶段；
- 数据泄漏检查通过；
- 相比预注册基线，净费用后指标有稳定改善或明确降低尾部风险；
- 引用、格式、超时和资料不足率在可接受范围；
- 模型不可用时能安全降级；
- 完整回放、回滚开关和审计记录可用。

模型版本、prompt、schema、证据构造或权限发生变化，都开始新的实验版本，不能把前后样本直接合并。

## 推荐实现顺序

### 第一个迭代：选股影子排序

1. 实现 Evidence Packet 和数据质量门；
2. 冻结每日基础池；
3. 新增结构化 LLM 排序，不改变现有观察池和交易；
4. 保存全量排名及 1/3/5/10 会话结果；
5. 页面显示“LLM 研究候选”和“策略可执行提案”的明确区别。

这是当前最值得先做的部分：它能显著扩大 LLM 的研究覆盖面，又不会把尚未验证的模型判断直接传到订单层。

### 第二个迭代：买入评审增强

补充市场状态、事件风险和反对证据；引入稳定原因码、反事实结果和离散计划模板。保持人工批准及程序仓位计算。

### 第三个迭代：持仓 thesis ledger

在影子模式运行每日/事件复核，记录逻辑变化和提前退出建议，与现有程序退出逐笔对比。积累数据后，允许模型生成需要人工确认的提前退出提案。

### 第四个迭代：权限评估

使用锁定样本外数据评估选股、买入、卖出三个环节各自的增量价值。只升级通过门槛的单项权限；不整体切换成“LLM 自动交易”。

## 首个迭代验收条件

- 相同输入、模型版本、prompt 版本和研究批次可以完整重放；
- 基础池、未入选股票和模型空列表都保存，不出现幸存者偏差；
- LLM 不能加入未通过可交易资格的代码；
- 所有事实引用有效，未来、陈旧或冲突数据明确标记；
- 模型失败或超时不会改变现有观察池、策略扫描和订单；
- 研究建议不会创建 proposal、approval 或 order_intent；
- 后续收益按当时可得数据和统一价格规则计算；
- 页面明确标记“研究建议，不是交易信号”；
- 完整单元测试和现有执行回归全部通过。

## 可以直接用于编码的任务说明

> 为 quant_us-main 实现第一阶段 LLM 选股影子排序。在不改变现有观察池、策略阈值、审批规则、仓位计算和订单行为的前提下，为每日可交易基础池生成版本化 Evidence Packet，并让 LLM 输出结构化 Top-N 研究排名。冻结并持久化完整基础池、输入快照、模型/prompt/schema 版本、排序理由、支持与反对证据、资料缺口和空列表结果。LLM 不得加入基础池之外的代码；失败、超时或无有效引用时只记录失败，不修改交易状态。为所有候选记录统一的 1/3/5/10 会话结果，供规则排序与 LLM 排序离线比较。建议页必须把研究候选与可执行交易提案明确分开。补充输入确定性、账户隔离、证据引用、越权代码、模型失败、重复批次、空列表和无订单副作用测试，并运行完整执行回归。
