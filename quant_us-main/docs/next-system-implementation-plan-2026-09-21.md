# 买入、卖出与 LLM 增量：下一阶段技术落地规划

日期：2026-09-21。状态：实施规划；不是试验预登记，不表示参数已验证或实盘已获授权。

## 0. 系统建设的主要目的

本规划遵循用户长期目标：

1. 筛选更有效的买入、卖出策略。
2. 提升 LLM 在完整决策链条中的实际贡献。
3. 在控制回撤与尾部风险的同时，提高胜率和扣除交易、模型成本后的收益。

买入侧必须建设可执行、可验证的“抄底信号”；卖出侧下一步主攻“持仓退出与利润保护”。两侧都做建设性优化。工程、测试、对拍、登记都是手段，不以模块数量或模型调用次数作为成果。

收益、胜率、盈亏比、回撤、尾部风险联合报告。提高胜率但损害长期净收益，不算整体目标达成；改善风险但牺牲收益的版本只能标为权衡方案，不能宣称全面优于基线。不承诺每轮实验都会提高收益。

不接入公司事件源。价格、成交量、技术特征、市场状态、账户状态仍可构成 LLM 的结构化输入；“不接公司事件”不等于“只能给模型市场新闻”。

## 1. 继承已有成果，不重复建设

| 已有成果 | 本轮用途 | 保留的边界 |
|---|---|---|
| B3 入场、初始止损、H60 | 固定对照策略 | 不把当前基线称为最优策略 |
| 行情、分红会计、事件重放、跨引擎对拍 | 复用数据和账户基础 | 对拍不能排除共享缺陷，实际覆盖范围随报告披露 |
| H3、H-A 失败记录 | 保留硬止损、日线确认作为对照 | 不重开同一试验、事后调门槛 |
| 行业分解 | 分离科技暴露与策略规则贡献 | 历史行业优势不是未来保证 |
| 诊断漏斗、退出归因 | 找到受影响机会和损益来源 | 通过率低不等于过滤无效 |
| R/L、持仓评审、权限和应用事件 | 复用 LLM 调用到动作执行链 | 真正改变纸面路径才算参与；参与不等于有效 |
| B3 三臂前向观察 | 原方案继续积累样本 | 不改冻结代码、池子、起点或评估规则 |

历史窗口已被查看，只用于探索和淘汰明显无效方案。正式资格来自新登记的前向数据。不能为等待旧实验的长期评估点而停止新策略研究。

## 2. 总体实施顺序与依赖

第一批：隔离研究版本 + 一个机械利润保护变体 + 完整对照报告。
第二批：一个趋势回撤型抄底信号 + 独立买入对照报告。
第三批：一个 LLM 持仓退出角色 + 真实 R/L 纸面动作和成本报告。
第四批：对值得保留的单项方案启动独立前向验证；只有单项证据足够时再研究买卖组合。

第一批开发期间同步完成第二批信号规范，不能等卖出前向验证结束才做买入。第三批的特征契约可同步设计，收益试验按独立登记顺序进行。不依靠同时跑大量方案挑赢家。

每批完成定义：代码可执行、输入可追溯、失败边界经过测试、结果可复现、明确保留/拒绝/不可判断及下一动作。登记与文档本身不算策略进展，但缺少必要的时序或会计正确性时不能跳过验证。

## 3. 版本隔离与最小架构

### 3.1 保护正在运行的前向实验

当前 `forward_arms.py::FROZEN_CODE` 包含 `paper_engine.py`、`candidate_adapter.py`、`schema.py`、`experiments.py` 等核心模块。不能为了新变体直接修改这些文件。

实施起点记录当前 git commit、工作区差异、现有冻结哈希及运行目录。新研究使用独立 checkout/worktree；调度命令绑定明确的代码路径与环境，不能依赖默认工作目录。旧前向任务继续使用原 checkout，不迁移、不重启。新研究允许改引擎，但必须有新版本与新 manifest。回合结束做旧冻结集不变检查。

不要另造账户引擎。在隔离版本中给现有引擎增加有限的退出策略接口和必要状态；关闭新功能时与原 B3 逐事件、逐日状态一致。上线到研究调度前固定该版本，后续编辑不能污染已开始的新观察。

### 3.2 拟新增模块（名称是实施建议，不是已存在命令）

| 模块 | 职责 |
|---|---|
| `scripts/strategy_research/protocol.py` | 本轮研究配置、版本身份、登记绑定与校验；复用既有哈希和登记工具 |
| `scripts/strategy_research/exit_policy.py` | 唯一机械利润保护规则，输出下一交易日生效的保护线 |
| `scripts/strategy_research/bottom_signal.py` | 回撤企稳状态机及信号原因 |
| `scripts/strategy_research/technical_packet.py` | 程序计算、带时间戳与缺失语义的技术证据包 |
| `scripts/strategy_research/runner.py` | 单项对照编排、输出隔离；复用原账户和诊断模块 |
| `scripts/strategy_research/report.py` | 四类结果：买入信号、退出动作、LLM 影响、账户效果 |

优先扩展既有登记、store、reviewer、report 能力，不为每个策略重写基础设施。研究产物放在 `data/strategy_research/<study_id>/`，生产账本不作为写入目标。

## 4. 第一批：持仓退出与利润保护

### 4.1 假设与唯一差异

假设：原初始止损维持较大盈利回撤空间；趋势获利后收紧保护可能减少回吐和账户下行损失，但也可能截断大赢家。不能从“当前价到止损距离大”直接推导应当收紧。

A：原 B3 入场 + 初始硬止损 + H60。
B：完全相同的入场、初始止损、H60、风险预算、池子、费用，增加一套机械利润保护规则。

第一版建议使用“获利激活 + ATR 跟踪”，不同时测试均线退出、分批止盈、延长 H60 等其他改动。

参数规范：初始风险 R0 固定；最高已完成收盘价 H 随时间更新；浮盈达到激活门槛后，候选保护线为 H − k×ATR；新保护线取旧保护线与候选线的较高者。激活门槛、k、ATR 算法及预热长度在预登记中填写为具体值；缺失任一值 runner 拒绝执行。参数依据规则解释力和既有策略约定确定，不先跑网格再选。

### 4.2 时间、行动和执行

- T 收盘完成后计算特征与新止损；记录 `observed_at`、`effective_session=T+1`。
- T 的最高/最低价不能用于生成一条在 T 已生效的止损。
- 新保护线若高于下一开盘，按开盘触发跳空退出，不假定能在保护价成交。
- ATR 缺失时保持已生效保护线，标记数据不足，不放宽硬止损。
- 拆股后数量、成本、最高收盘锚点和保护价按同一比例调整；分红的价格基准按既有会计规则一致处理，区分机械公司行动调整与主动放宽止损。
- H60 继续有效。跳空止损、盘中止损、时间退出冲突时，沿用冻结优先级并写入事件。
- 收盘特征构建失败时原退出路径继续工作，不能因诊断失败失去保护。

### 4.3 状态与事件

新增状态仅限：`initial_risk_micro`、`highest_completed_close_micro`、`protection_activated`、`pending_stop_micro`、`effective_session`、`exit_policy_version`。

新增事件建议：`protection_activated`、`stop_update_scheduled`、`stop_update_applied`、`policy_data_unavailable`。每个事件绑定持仓生命周期而非仅证券代码，防止再入场继承上一笔高水位。事件键包含研究、账户、持仓、会话及策略版本，重复运行同内容幂等、异内容冲突；重放能完整还原新状态。

### 4.4 评测与判断

先固定同一批机会做退出对照，再使用完整账户验证现金、容量、再入场与回撤阶梯的路径影响。机会级结果不得相加冒充账户超额收益。

本轮主要风险指标建议为账户日收益下尾 5% 的 Expected Shortfall（转为正损失量，越小越好）；最大回撤、恢复时间及最差单笔作为关键辅助。收益约束为全成本终值收益差不得低于预登记的非劣界限。风险改善幅度、非劣界限、最小成熟组数与评估点必须在计算前数值化。

统一报告：扣费收益、胜率、平均盈亏比、MDD、尾部损失、浮盈回吐、换手、触发次数、卖后路径、贡献集中度、1×/2×成本。止损的回吐上界不是最大可能损失，跳空与流动性风险另列。

判断至少区分：风险改善且收益守住 / 风险改善但收益牺牲 / 无改善 / 样本不足 / 工程阻塞。只有胜率和收益同时提升、风险未恶化时才可宣称本轮同时支持三个绩效方向。仅风险改善可以形成防守选项，但不得写成全面优胜。

## 5. 第二批：买入抄底信号

### 5.1 产品定义

第一版“抄底”限定为上升趋势中的回撤企稳，不尝试识别所有熊市最低点。采用独立买入变体，与 B3 对照；不默认把新信号叠加进生产交易。

状态：`INELIGIBLE → WATCH → TRIGGERED → EXPIRED/INVALIDATED`。触发后的成交、账户拒绝、数据阻塞单独记录，不能混成信号成功/失败。

- 资格：沿用相同股票池、质量要求及可交易性。
- WATCH：长期趋势条件成立，且从过去已完成高点回撤达到预登记的价格/ATR 条件。
- TRIGGERED：出现一项明确的价格恢复确认。均线回收、前日高点突破等只选一种，不合成多个事后可解释条件。
- INVALIDATED：趋势破坏、超出风险距离、关键数据缺失；EXPIRED 为超过等待窗。
- 全部窗口、阈值、触发频率、冷却期与再入场规则在开算前固定。

市场门、排名与等待窗是否沿用必须逐项写在 manifest。若替换了整个 B3 入场包，这是一个“新入场策略”的比较，不能声称只移除了日线过滤。H-A 原结论不重开。

### 5.2 用户可见输出与记录

每个信号包含证券、候选轮次、状态、数据截止时间、回撤深度、趋势/企稳条件、信号日、最早执行日、初始风险距离、失效原因和版本。信号不是预测的真实底部；不给未经校准的“成功概率”。

首次触发固定信号身份；次日开盘跳空导致定仓无效时记录未成交，不回填更漂亮的入场价。观察名单和可执行买入意图分开展示。

### 5.3 实验

沿用原退出规则测试新入场；不把第一批的新退出同时接入。双方共用数据、日历、成本和账户风险限制。

报告共同机会、新增机会、原策略独有机会、账户拒绝机会；同时呈现新增盈利和新增亏损。候选截止日仅依共同可观察期限决定，不按最终是否提前止损选择样本。披露不同信号密度，不强行把不对应的交易配成一对。

主要目标为全成本账户收益改善；胜率、盈亏比、MDD、尾部风险是必须报告与预登记约束。机会级 MAE、触发后失效率用于解释，不替代账户结果。输出明确的保留、拒绝或证据不足结论。

## 6. 第三批：LLM 持仓决策的真实增量

### 6.1 先限定一个角色

第一轮只做持仓 `HOLD / EXIT / ABSTAIN`。不同时开放买入、加仓、自由仓位、自由止损参数。硬止损不可取消或放宽。R 按冻结机械退出；L 保留同一硬保护，允许有效 EXIT 在下一个可执行开盘生效。

复用 `position_review.py`、`position_packet.py`、`position_overlay.py` 与既有 store/权限流程。现有评审以 R 持仓为主体，可避免 L 提前卖出后改变后续评审分母；L 已无该持仓时记 `ignored_not_held`，不伪装成执行成功。

### 6.2 技术证据契约

程序负责计算趋势位置、回撤、ATR、量能、持有期、浮盈/R、保护距离、风险状态和现金暴露。每项包含数值、单位、算法版本、as_of、available_at、来源及缺失原因。模型不计算股数、收益或 ATR。

技术包需独立、显式的充分性标准，不能伪造公司事件以绕过原新闻质量门。市场摘要为可选输入；缺失时按登记规则降级或 ABSTAIN，不能随运行情况随意切换模式。

模型输出绑定 packet hash、模型标识、prompt/schema 版本、决策截止时间、动作和理由码。晚到、非法、越权或错包输出不应用；默认继续机械规则，保留原因与实际调用费用。

### 6.3 公平比较与权限

R 与 L 同输入机会、同资金起点、同费用与风险限制；另明确机械比较者与模型可用的信息、评审时点和可选动作。机械退出不能被人为限制得更弱来制造 LLM 优势。

在独立研究权限配置中允许纸面应用，必须真实写 application 并改变该账户意图；不修改生产默认 shadow 权限。先用合成输入验证执行链，然后用真实前向数据与真实模型验证贡献。夹具调用不计真实覆盖率。

历史 LLM 调用可能含模型知识穿越，不能作为正式收益证据；模型研究的资格判断以实时冻结证据、决策在执行前生成的前向记录为准。

验收：有效评审覆盖、可追踪完成率、实际应用、路径变化、未应用原因、模型费用、L−R 终值与风险差。零个路径变化可以是自然结果，不能为了展示作用强迫交易；此时不能声称已证明收益贡献。

## 7. 统一指标与结果解释

- 单笔风险：使用成交时冻结的初始风险金额作为净 R 分母，不随浮盈变化。
- 入场风险预算与当前保护距离分开命名；不把两者相除称为同一预算使用率。
- 胜率只统计已平仓净盈利交易；未平仓计入账户 NAV 和右删失清单。
- 年度收益由 NAV 计算，交易退出年归因另表展示。
- 报告收益、风险差及不确定区间；相关机会按时间块或预登记聚类单位处理，不把同股相邻信号当独立随机样本。
- 单证券贡献与剔除最大贡献后的结果必须报告。集中不证明永远无效，但不能据此宣布可推广。
- 预登记固定主指标、数值门槛、成本情景、最小样本、首次评估点、失败停止条件及不确定结果的处理；不得延长到显著。
- 历史探索、前向纸面有效、生产可上线是三个不同状态。通过实验不自动提高权限。

## 8. 测试与验收矩阵

| 验收项 | 必测边界 |
|---|---|
| 无未来信息 | 修改未来行情不改变既有信号；收盘更新只影响次日 |
| 原策略不变 | 关闭新策略后与冻结基线的机会、成交、费用、状态一致 |
| 保护执行 | 激活阈值两侧、止损只收紧、跳空、当天触发、H60冲突 |
| 公司行动 | 拆股/分红锚点一致，到期应收结算、未知支付日不伪造 |
| 事件恢复 | 写入前后中断、重复运行、异内容冲突、重放一致 |
| 抄底信号 | 观察与触发分离、失效/过期、再入场冷却、数据末端成熟度 |
| LLM | 超时、晚到、越权、非法JSON、错包、已平仓、费用未知与补记 |
| 账户公平性 | 相同成本/日历/起点；容量与现金拒绝可解释，风险状态一致处理 |
| 冻结保护 | 原前向哈希不变，新观察绑定明确代码版本 |

复用 pytest 现有单元测试结构，新增行为的测试必须能在注入对应缺陷时失败。每个可交付批次运行相关测试及项目完整单元套件；不重复测试只为增加数量。

## 9. 分批交付与完成条件

| 批次 | 核心交付 | 完成条件 | 下一步 |
|---|---|---|---|
| S1 卖出 | 一个退出变体、逐笔及账户对照、风险收益权衡报告 | 可复现执行与实际结果；无论正负都留存 | 值得保留则冻结独立前向，否则保留原退出 |
| B1 买入 | 一个抄底信号、观察/触发/失效输出、B3 对照 | 新增机会的盈亏与账户影响可解释 | 值得保留则独立前向，不等 S1 前向结束 |
| L1 模型 | 技术包、限定角色、R/L 真实纸面应用 | 真实评审可追踪，费用入账，路径和结果可比较 | 按登记评估，未证明有效不扩权 |
| C1 组合 | 条件成立后才比较新买入与新退出组合 | 单项有证据基础，单独登记交互效应 | 不默认两个局部改进叠加必然更好 |

不按日历承诺收益验证完成；开发交付与样本成熟分别记录。现有长期前向观察仅在异常或登记评估点需要介入，不围绕它持续搭建新工具。

5. 执行同机会对照；符合登记继续条件才跑完整账户对照。
6. 输出“保护了多少、牺牲了多少、是否值得继续”的结果报告。
7. 同批交付抄底信号的具体状态与参数规范，下一批直接进入实现，不再从泛泛讨论开始。
