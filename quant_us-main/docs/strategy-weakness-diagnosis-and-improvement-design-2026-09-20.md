# 策略薄弱环节诊断、单项改进与 LLM 增量验证——详细技术设计

- 日期：2026-09-20
- 状态：设计稿；本文件不表示相关功能已经实现、实验已经通过或生产权限已经变更。
- 目标系统：`quant_us-main`；参考研究：同级目录 `gs_backtest`。
- 用户约束：不接入公司事件；使用已有行情、技术指标、市场状态和账户信息。
- 第一交付目标：找出一个有数据支持的主要收益损失来源，完成一项针对性改进的对照验证。若证据不足，则交付“尚不能改”的明确结论。

## 1. 决策摘要

本轮不预设“买入太严”“卖出太早”或“LLM 应该多否决”。当前确认的缺口是收益归因与真实前向样本不足，而不是某条交易规则已经被证明无效。

工作按以下顺序推进：

1. 冻结当前规则、数据和执行口径，建立可重放的基线。
2. 记录完整买入漏斗，拆解退出、容量和资金闲置的来源。
3. 在研究区识别一个最值得检验的问题，冻结单项改动。
4. 用同一账户引擎比较原方案和改动方案，再进入预先锁定的前向观察。
5. 只有存在可定义、可评估的剩余决策问题时，才让 LLM 参与纸面决策。

四组对照是后续区分入场、退出与交互作用的工具，不是第一阶段必须同时运行的四个开发项目，也不是收益提升的保证。

### 1.1 成功与失败都必须可交付

可接受结论包括：

- 某项改动在预注册口径下具有稳定增量，建议进入前向纸面观察。
- 改动只通过降低暴露减小回撤，不能称为提高收益。
- 改动效果依赖单一证券或特定时期，保留原策略。
- 当前信号少但过滤有效，不应为了增加交易放宽规则。
- 数据、执行或结果成熟度不足，无法判断。

不接受以“新增若干指标/角色/测试”“有效输出率提高”“历史最佳收益更高”代替收益贡献证据。

## 2. 事实基础与边界

### 2.1 已核对的实现

| 对象 | 已存在的能力 | 本设计如何使用 |
|---|---|---|
| `scripts/portfolio_shadow/candidate_adapter.py` | 月度候选、周线门、日线择时、等待窗；增量候选生成 | 扩展可解释漏斗，不另写第二套正式入场规则 |
| `scripts/medium_term/timed_entries.py` | 完整周门、突破/回踩定义、参考日历等待期 | 复用特征语义，记录每一道门的结果 |
| `scripts/portfolio_shadow/paper_engine.py` | 整数微美元、实际股数、现金、公司行动、硬止损、期限退出 | 作为账户实验的主结算引擎 |
| `scripts/portfolio_shadow/store.py`、`replay.py` | 状态、事件、持久化与重放 | 每组独立实验身份，验证重放一致 |
| `scripts/portfolio_shadow/report.py` | 配对收益、回撤、模型费用和动作追踪 | 复用底层数据，增加诊断报告 |
| `scripts/medium_term/exit_matrix.py` | 多种退出研究与固定期限结果 | 用作规则参考与独立对拍，不混用两个引擎的账户收益 |
| `scripts/live_trading/decision_ledger/promotion_review.py` | 晋级资格审计 | 后期消费可信指标；本设计不自动提升权限 |

当前影子父策略通常称为 B3@60@1%，但实际参数必须从被选中的冻结 manifest 读取。文件中的示例不得覆盖真实基线参数。实盘决策层、影子实验、历史研究矩阵是三个不同的数据来源，不得合并计数。

当前影子硬止损默认距离为 `max(8% × 入场价, 2.5 × ATR)`，另有期限退出；这不足以证明止损过紧或期限退出过早。现有其他研究模块即使支持更多退出，也不代表影子引擎已经应用它们。

### 2.2 从 gs_backtest 借鉴什么

借鉴：简单机械基线、单因素替换、按证券/时期分解、剔除新股敏感性、生产状态机与冻结基准逐日对账。

不直接采用：40 日最短持有、25% 止损、8×ATR、7% 仓位上限及对应收益结论。原因如下：

- 样本是事后选取的 AI 产业链股票，结论仅适用于相应条件。
- 收盘信号按同一收盘价成交，不等同于本系统 T+1 执行。
- `backtest_portfolio.run_portfolio` 每日使用目标权重，却仅按目标权重差计费；价格漂移产生的隐含再平衡没有完整计费。不能把其结果当作固定股数账户。
- walk-forward 测试窗口有重叠，不能按独立试验次数累计可信度。
- 对账通过只能证明与冻结基准一致，不能排除双方共享的会计或时序错误。

局部复现：股票/现金各 50%，股价 100→200→100，固定股数账户终值为 1.00；该权重引擎为 1.125，目标权重未变导致中途再平衡成本为零。移植应移植规则定义，不能复制这套收益计算。

### 2.3 本轮不做

- 不接入公司新闻、公告或事件供应商。
- 不改变实盘配置、自动下单权限、现有冻结实验或历史决策。
- 不使用今天的模型输出回填历史 LLM 决策。
- 不把合成候选、夹具或历史调试样本算入真实前向验收。
- 不要求新增退市股票源；继续披露所选存续股票池的条件性结果和幸存者偏差。
- 不在同一轮同时放宽入场、放宽止损、增加仓位并打开模型减仓。

## 3. 研究问题与诊断顺序

| 编号 | 假设 | 必须观察的证据 | 不足以证明它的现象 |
|---|---|---|---|
| H0 | 收益缺口来自数据或调度失效 | 应运行却缺失、数据陈旧、有效候选未在截止前执行 | 单纯交易少 |
| H1 | 某道入场过滤净贡献为负 | 单独移除该过滤后，可执行账户净收益改善且风险可接受 | 被过滤的一只股票后来上涨 |
| H2 | 期限退出过早截断趋势 | 相同入场/硬止损下趋势退出改善账户收益 | 卖后最高价高于卖价 |
| H3 | 硬止损过紧 | 独立止损变体在相同账户风险预算下改善结果 | 止损后短期反弹 |
| H4 | 容量或排序浪费机会 | 相同现金、槽位和风险约束下另一确定性分配更好 | 未成交股票跑赢已成交股票 |
| H5 | LLM 可改善剩余判断 | 冻结模型在真实前向窗口中优于机械对照，扣除全成本 | 文案合理、模型置信度高 |

先排除 H0，再处理 H1/H2/H4；H3 另立实验，避免扩大止损同时改变定仓导致无法归因。H5 最后开展。

## 4. 数据与冻结契约

### 4.1 研究 manifest

新增研究专用 manifest，不把以下未知字段直接塞入现有 `Manifest`（现有 schema 会拒绝未知键）。研究 manifest 引用各组已冻结的影子子 manifest。

必填字段：

```yaml
schema_version: strategy-diagnostic-v1
study_id: REQUIRED
status: DRAFT
baseline_manifest_path: REQUIRED
baseline_manifest_hash: REQUIRED
code_revision: REQUIRED
working_tree_hash: REQUIRED
universe_snapshot_hash: REQUIRED
calendar_hash: REQUIRED
prices_hash: REQUIRED
corporate_actions_hash: REQUIRED
quality_hash: REQUIRED
research_window: {start: REQUIRED, end: REQUIRED}
validation_window: {start: REQUIRED, end: REQUIRED}
validation_kind: REQUIRED # historical_holdout 或 prospective
prior_exposure_to_validation: REQUIRED
initial_state_policy: flat_common_start
primary_metric: full_cost_terminal_return_delta
entry_policy: REQUIRED
exit_policy: REQUIRED
execution_policy: REQUIRED
risk_policy: REQUIRED
cost_policy: REQUIRED
statistical_protocol: REQUIRED
trial_registry_path: REQUIRED
```

冻结时还必须声明：最大并发仓位、单票上限、风险预算、容量排序、等待窗、再入场规则、成交缺失处理、历史数据使用范围、观测结束规则及成本压力假设。缺失不得靠代码默认补成可交易实验。

`working_tree_hash` 仅覆盖被执行源码和配置，排除凭证、产物与运行时间。所有组使用同一输入快照；不同输入不得直接配对。

### 4.2 时间与价格

- 规则在交易日 T 收盘后生成，最早执行 T+1 开盘；使用真实参考交易日历。
- 技术指标由程序计算；LLM 不自行计算 ATR、均线、仓位或收益。
- 信号特征使用截至 T 可得的公司行动一致价格视图；成交使用实际交易价格和对应股数。
- 不能用未来拆股/分红信息过滤历史候选；结果不可结算与决策当时不可交易分开记录。
- 缺关键价格：标记不可执行或估值暂定，不补造开盘成交。
- 预热不足：标记 `WARMUP_INCOMPLETE`，不把未知市场状态默认当放行。
- 不因缺少未来 60/120 根 K 线从前向候选池删除机会；未来结果单独标 pending/censored。
- 不同股票缺行情不能让参考日历缩短，不能延长等待窗或持有期。

### 4.3 结果成熟与右删失

账户层：在共同估值日盯市，未平仓头寸仍进入 NAV，不能只汇总已平仓赢家。

交易层：完整交易才进入最终已实现胜率；未平仓、停牌、样本尾部不足单独列出。固定 5/20/60 日标签仅统计相应期限已成熟的共同样本，并同时披露未成熟比例。

## 5. 买入漏斗设计

### 5.1 三层实体

1. `candidate`：一个证券在一次月度候选轮次中的身份。
2. `gate_observation`：该候选在某交易日、某阶段的一次评估。
3. `account_application`：某账户对 READY 机会的执行结果。

不得用“每天一次 WAITING”冒充多个独立候选；不得把账户容量拒绝伪装为策略入场拒绝。

### 5.2 阶段与输出

| 阶段 | 记录内容 |
|---|---|
| 股票池/数据资格 | 是否属于当期池、资产类型、行情/公司行动/预热质量 |
| 市场门 | 指数、均线、实际阈值、通过/拒绝/未知 |
| 月度排名 | 分数、名次、top-N、未入选原因 |
| 周线门 | 最近完整周、周均线与斜率、数据截止 |
| 日线择时 | 突破/回踩条件及数值、首次触发日 |
| 等待窗 | 起止 session、已等待长度、到期原因 |
| 账户资格 | 已持有、槽位、现金、单票/组合风险、前序候选占用 |
| 执行 | 计划日、实际日、成交或未成交原因、调度状态 |
| LLM（后期） | eligible/called/valid/effective/applied/fallback 与费用 |

每阶段分别报告条件通过率和端到端通过率；分母为零显示 unavailable。

### 5.3 observation 字段

```text
study_id, candidate_id, security_id, candidate_round
session, stage, result(pass/reject/unknown/not_evaluated)
primary_reason, all_reasons[], input_snapshot_hash
feature_values{}, thresholds{}, observed_at, generated_at
rule_version, source_kind(historical_reconstruction/live_observed)
```

稳定键为 `(study_id, candidate_id, session, stage, rule_version)`。同键同内容幂等，同键异内容冲突；更正需新版本。墙钟审计字段不应导致同一次历史确定性重放产生新业务身份。

同时满足多个拒绝条件时记录所有可计算的条件，以固定优先级选主原因用于漏斗守恒。未执行的后续条件标 `not_evaluated`，不能当失败。可额外计算影子条件向量作相关性诊断，但不得计为已实际通过该阶段。

历史缺少调度记录时只能重建规则条件，不能声称历史系统确实执行过。

### 5.4 被过滤机会的跟踪

单纯看其后涨幅仅用于描述，不能给过滤器定功过。

对待评估过滤器 F：

1. 构造仅移除 F 的机械策略，保留其他规则。
2. 使用该策略第一次合法触发时刻确定候选入场，不能事后选最低点。
3. 若移除 F 后仍未满足其他条件，则不生成虚构交易。
4. 先计算固定单位风险的机会级结果，再运行有限资金的完整账户。
5. 对“原策略错过、放宽后赚钱”和“原策略避开、放宽后亏损”同时统计。

机会级收益差不能相加作为组合增量：多个机会可能竞争同一份现金或仓位，改变入场还会改变后续机会。最终裁决只使用账户重放。

## 6. 退出损益拆解

### 6.1 已有交易记录扩展

每笔交易关联 `entry_id`、原始机会、实际入场数量、初始风险金额、所有部分卖出、最终退出原因、成本、公司行动与持有 session 数。拆股前后保持经济身份一致，Position 连续动作按整笔交易汇总。

退出原因至少区分：`GAP_STOP`、`STOP`、`TIME_EXIT`、`TREND_EXIT`、模型退出/减仓、数据终止。数据终止不得归类为成功或失败的策略离场。

### 6.2 诊断指标

- 各退出原因的笔数、持有期、净损益、净 R、对账户收益贡献。
- 退出后 5/20/60 session 的总回报、最大有利/不利变动和成熟比例。
- 止损后恢复至入场价的比例、恢复耗时，以及未恢复比例。
- 到期退出时趋势仍完整的比例；按新趋势规则实际持有后增加的收益与回撤。
- 盈利回吐仅作为描述；不得使用未来最高点作为“本来能赚到”的收益基准。

`net_R = 含分红及全部交易费用的实际损益 / 冻结的初始风险金额`。初始风险为零/无效则 unavailable；跳空损失允许小于 −1R，不截断。

### 6.3 第一候选退出规则

仅在退出诊断支持 H2 时测试 `MA20_60_NEXT_OPEN_V1`：

- T 收盘满足 `close <= MA20 AND close < MA60`，生成 T+1 开盘退出意图。
- 均线必须有效；指标缺失不产生趋势退出，原有硬止损仍有效，并记录质量状态。
- 不引入 40 日锁仓，不改变硬止损、定仓和手续费。
- 替换原 H60 期限退出；观察结束时未平仓按市值估值并作右删失，不伪造已完成交易。
- 不新增每票 120 日强平作为隐含第三条规则。如需最长持有期，应另注册变体。
- 对相同证券的重复入场、轮次身份和容量排序沿用原规则。

必须新增明确的退出策略分派，禁止把 `horizon` 偷改成巨大整数来实现“没有期限退出”。

### 6.4 引擎阶段顺序

沿用既有资金结算、公司行动、开盘风险退出等顺序。在开盘风险退出后、当日新仓入场前消费此前冻结的趋势退出意图。跳空止损与趋势退出同日发生时只成交一次，优先记 `GAP_STOP`，保留被覆盖意图的原因。

T 收盘趋势信号不得在 T 开盘或 T 收盘回填成交。研究运行器逐日 prepare→execute→mark，不得先读取全日结果再决定当日开盘动作。时间退出若原基线是预定收盘退出，原样保留，其可执行性与依赖收盘价才确认的趋势信号不同。

新阶段必须进入事件账本与 replay，旧策略路径的状态哈希保持一致。

## 7. 容量、现金与风险归因

### 7.1 账户会计

所有变体复用真实股数和现金账户；不把固定权重收益序列当作固定股数持有。

- 每笔成交消耗/释放真实现金，卖出款按既有结算规则释放。
- 不因股票涨跌自动再平衡，除非新实验显式定义并对实际交易计费。
- 股数由冻结单笔风险预算、实际止损距离、单票上限和可用现金共同约束。
- 公司行动按同一输入、同一时间处理。
- 每日验证现金非负、股数合法、风险和仓位限制以及 NAV 会计恒等式。

### 7.2 报告

记录现金闲置日数和比例、暴露、槽位占用、风险预算使用、已持有拒绝、资金不足、容量排序拒绝及每种原因的机会数。

现金闲置不自动定义为损失。另列“若配置基准资产”的描述性机会成本，但不加入主收益，也不据此默认投资全部现金。

排序替换实验必须使用同一候选集、同一容量与成本；不能拿资金无限的机会收益排序充当可交易排序能力。冻结并列规则，缺排序字段不随机补齐。

## 8. 实验设计与实施顺序

### 8.1 D0：基线复现和漏斗

只运行现有策略。产出阶段通过率、候选终态、退出分类、容量与运行缺口。基线必须与已有冻结实验在共同输入与日期上对齐；不一致先解释，不开始寻优。

### 8.2 D1：一个问题、一个改动

在研究区选定唯一主要假设和一个 challenger。优先级依据可执行收益差、影响覆盖、独立样本与实现风险共同判断；不能只按最大历史利润选。

若当前证据不足以选出问题，D1 结束于 `INSUFFICIENT_EVIDENCE`，不为了完成项目任意改策略。

### 8.3 D2：必要时运行四组因子对照

| 组 | 入场 | 退出 |
|---|---|---|
| A | 当前 B3 | 当前退出 |
| B | 简化入场 | 当前退出 |
| C | 当前 B3 | 趋势退出 |
| D | 简化入场 | 趋势退出 |

第一版“简化入场”固定为：保留当期月度入选池、市场门、数据门、等待窗、排序；把周线门＋突破/回踩择时模块替换为等待窗内首次 `close > MA20`，T+1 开盘执行。它不是完整 G/S 移植，也不能区分周线门与日线条件各自贡献。若需要解释单道门，回到 D1 单独消融。

每轮候选的再次入场限制沿用 baseline，不能让 B 因更频繁重复入场获得额外试验次数。不得比较“G/S 固定 15 只全池”与“本系统月度前五”后把差异都归入买卖策略。

终值收益差记为：

```text
entry_effect = R_B - R_A
exit_effect = R_C - R_A
interaction = (R_D - R_C) - (R_B - R_A)
total_effect = R_D - R_A
```

这里 R 为同初始资金、同起止日、全成本账户收益，不是年化比率。上式是描述性因子分解；容量和路径依赖会产生交互，不能解释为逐笔独立因果效应。不同组交易无需逐笔强行配对，账户按共同交易日配对。

### 8.4 D3：冻结后的样本外/前向验证

历史研究区可用于定位问题；任何已经查看或用于选参的区间均不得再命名为真正未见样本外。登记研究者和模型是否接触该区间。

历史保留区确实未被使用时可做一次验证；无法证明则只列“历史稳健性”，正式资格来自后续真实前向窗口。验证窗口之间不重叠；训练/验证边界对未结束交易和标签跨度作显式隔离。

第一版账户验证选择共同空仓起点，预热仅计算指标，不把训练区策略挑选出的头寸带入验证。切分边界附近的结果标签不得进入训练选择。最终观察期内不更换规则、prompt、模型、成本和股票池定义。

## 9. 统计与验收口径

### 9.1 主指标和辅助指标

主指标：共同起止日的 `challenger 全成本终值收益 − baseline 全成本终值收益`。

必须同时报告：最大回撤及其差、年化波动、平均/最大暴露、换手、成交笔数、现金使用、盈利/亏损贡献集中度、未完成交易和数据质量。Sharpe/Calmar 为辅助指标，不能替代主目标。

模型成本未知时净收益为暂定上界，禁止判定通过。手续费与滑点使用可追溯配置；提供预注册的双倍成本压力情景，不选择最有利的成本口径。

### 9.2 相关性与不确定性

- 账户日收益按两组共同交易日对齐；用配对时间块重采样，所有证券与两组共享同一时间块，保留市场共振。
- 建议初版固定 20 session 块、2,000 次重复、固定随机种子，并以 10/40 session 为敏感性；块长不按最好显著性选择。
- 区间估计针对冻结策略已实现的配对收益差，不是未来盈利概率，也不消除策略选择偏差。
- 交易独立组至少包含证券与候选轮次/交易周；多期限结果不能重复计数；Position 按整笔 trade。
- 同时做 leave-one-security-out、年度/市场阶段切片。剔除证券时重新跑账户，不能只从收益表减去该证券，因为它释放的容量会改变路径。
- 历史年份切片用于稳健性描述，不冒充独立新实验。记录全部尝试，失败方案不得从试验登记中删除。

### 9.3 建议初版门槛

以下为研究设计默认建议，须在任何验证结果可见前写入冻结 manifest；不得在结果出来后调整。

| 层级 | 门槛 |
|---|---|
| 工程通过 | 基线对齐、无前视、账户守恒、重放一致、缺失信息可见 |
| 候选可进入前向观察 | 研究区净增量为正；失败机制可解释；成本压力和集中度检查无明显反证 |
| 初次前向评估 | 至少 30 个独立成熟组且至少 60 个交易日；两者均满足，否则继续观察或报告不足 |
| 证据支持纸面保留 | 主收益差为正，配对差异的 95% 区间下界大于零，双倍成本下仍为正，回撤未超预算 |
| 回撤预算建议 | `abs(MDD_challenger) - abs(MDD_baseline) <= 0.03`，即最多增加 3 个百分点；这是本实验建议值，不覆盖已有权限门槛 |
| 集中度 | 单一证券正贡献占全部正贡献不超过 50%；剔除最大贡献证券后重跑仍为正 |
| 生产变更 | 另行评审新版本与适用边界，原权限流程继续生效，不自动晋级 |

30 个样本只是最低观察条件，不是统计充分性的保证。交易稀疏时可能数月仍无法通过，不用日评审次数凑数。若区间跨零，结论为 inconclusive，不把“不显著”写成“已证明无效”。

结果判定枚举：`DATA_INVALID / ENGINEERING_BLOCKED / INSUFFICIENT_SAMPLE / NO_IMPROVEMENT / RISK_REJECTED / CONCENTRATED / INCONCLUSIVE / EVIDENCE_SUPPORTED`。

## 10. LLM 的位置：研究辅助先行，在线裁量后置

### 10.1 研究辅助

LLM 可读取程序计算好的错误分类、样本量、费用、收益和风险分解，输出待验证假设。不得自行重算收益、编造缺失字段、将未来标签送入在线特征，也不得自动改配置。

建议的研究假设输出：

```text
hypothesis_id, observed_failure_slice, supporting_sample_ids
proposed_single_change, expected_mechanism, competing_explanation
required_features, primary_metric, falsification_rule, limitations
```

LLM 看到的研究结果区间须写进试验登记；其建议会增加尝试数量，不能免除多重选择问题。

### 10.2 在线纸面实验

仅在机械规则改进后仍有明确情境判断需求时启动。第一轮只选 Entry 或 Position 一个角色，不同时开启多个角色。

现有无事件包可能被 `LLM_INSUFFICIENT` 短路；因此“只用量价”不是清空事件数组就自动可用。需要新建 `technical_feature_packet_v1` 契约和独立实验版本：

- 每个特征带 `feature_id/value/unit/as_of/source/quality/lookback`。
- 允许引用冻结特征 ID，程序校验数值和时间；不把量价特征伪装成新闻证据。
- 硬风控字段缺失禁止增加风险；普通辅助字段缺失可弃权，回到父策略。
- 若只用已有量价与账户信息，模型也不得补充记忆中的公司事件；不调用外部搜索。
- 输出只选程序给定的合法模板，不自行生成数量或保护价格。
- 准确记录 model_action/effective_action/execution_applied；shadow 只记录时不能声称产生收益。
- 无效、超时和弃权纳入覆盖率与成本，不从评估样本中删除。

LLM 至少对比两个基线：当前机械策略，以及研究区已冻结的简单替代规则。降低风险的模型还需比较预先校准并冻结的机械减暴露基线；不得用验证期结果反推一个最有利对照。

Entry 否决贡献必须同时包含避损与错失上涨。Position 采用连续路径重放，不把多个动作的短期收益相加。模型费用计入整个 L 账户，不仅计入改变路径的成功调用。

## 12. 存储、输出与恢复

研究目录建议：`data/strategy_diagnostics/<study_id>/`，与生产账本物理隔离。

```text
study_manifest.json
trial_registry.jsonl
input_index.json
funnel_observations.parquet
candidate_summary.parquet
exit_diagnostics.parquet
variants/<variant_id>/ledger.sqlite3
comparison.json
report.md

```

Parquet 是导出与分析格式，不承担执行事件权威账本；单账户执行与审计使用既有 SQLite 事务机制。依赖不可用时允许 CSV 导出，但 schema、空值和类型必须验证，不能悄悄改变语义。

- 冻结后同身份异内容拒绝；规则变更创建新 study/variant。
- 事件和对应投影同事务提交，重跑不修改已经结算结果。
- 不因历史调度缺口在今天补写过去的真实模型决策。
- 中断重启后不重复成交、不重复扣费，不复用另一版本的结果。
- 试验登记追加失败记录，不能删除失败变体以美化成功率。

## 13. 报告结构

报告首页必须回答：

1. 数据和运行是否足以判断？
2. 当前最有证据的薄弱环节是什么，另有哪些只是猜测？
3. challenger 相对 baseline 多赚/少赚多少，付出多少回撤与成本？
4. 改善是否依赖某只股票、时期或降低暴露？
5. 下一步是保留原规则、继续观察，还是进入新纸面版本？

后续附：漏斗、退出分类、现金/容量、共同时间轴净值、逐证券贡献、全部尝试清单、未成熟/不可用统计、输入与代码哈希、可重放命令。

所有表标清分母、收益单位（小数/百分比/百分点）、是否扣成本、数据截止日及历史/真实前向来源。不得把 gs_backtest 的票均收益和本系统账户收益放在同一栏直接比较。

## 14. 验证矩阵

| 测试 | 关键断言 |
|---|---|
| 观察器旁路 | 增加漏斗记录不改变原机会、成交和状态哈希 |
| 候选守恒 | 每个候选在指定日有唯一当前状态；WAITING 不是永久终态 |
| 双重拒绝 | 主原因固定，其他原因保留；未评估不算失败 |
| 未来截断 | 截断 T 之后输入，T 之前的信号和意图完全不变 |
| 前向成熟度 | 缺未来 bar 不阻止当时信号；结果保持 pending |
| 趋势退出时序 | T 信号只在 T+1 执行；未来 close 变化不影响 T 开盘 |
| 同日冲突 | 跳空止损与趋势意图只成交一次；不误卖新 trade |
| 资金占用 | 卖出款未结算不得被重复花费；满仓候选不得超配 |
| 权重陷阱 | 100→200→100、半股票半现金、无交易时 NAV 回到原值 |
| 公司行动 | 拆股不产生虚假损益，分红按原会计口径处理 |
| 窗口尾部 | 未平仓计入 NAV，交易统计标右删失 |
| 重跑/故障 | 半途失败回滚、重启可重放、无重复动作 |
| 分组统计 | 多期限/多次评审不膨胀独立样本，缺信息不可晋级 |
| 报告诚实性 | 零分母为 unavailable；未知费用不可判通过 |
| 新特征 LLM 契约 | 引用不存在/未来特征失败；空特征不调用；模型不能生成数量 |

每个关键回归应证明在注入对应缺陷时失败。先跑相关单测，再跑 `python3 -m pytest tests/unit -q`；研究联调使用临时目录或副本。禁止测试写入生产 JSONL/SQLite 或触发真实下单。

## 15. 分阶段交付与停止条件

### P0：口径冻结和基线对拍

交付：研究 manifest 校验、输入索引、基线复现、输出隔离。

验收：同输入与旧基线一致；确认没有数据/时序/会计阻塞。失败则停在工程修复，不运行收益寻优。

### P1：买入漏斗、退出和容量诊断

交付：可追溯的逐候选记录、退出分类、完整诊断报告。

验收：所有未成交原因可解释；历史重建与真实运行分开；报告明确一个候选假设或证据不足。

### P2：单项 challenger

交付：一个冻结规则差异、同口径账户重放、成本/集中度/时期敏感性、全部试验登记。

验收：只改声明变量；解释改善与代价。失败保留原策略，不顺手增加第二个参数补救。

### P3：必要的四组对照和前向验证

交付：因子效应与交互报告，非重叠且事先登记的观察窗口。

验收：满足第 9 节或明确报告不可判断。每周可查看运行健康，但收益裁决仅在预登记评估点作出；严重数据/风控失败可立即停止。

### P4：LLM 专项实验

交付：无公司事件的特征契约、一个角色、机械基线、真实前向费用与增量报告。

验收：收益依据来自实际应用的纸面动作，而非未生效建议；满足原有权限流程才讨论后续上线。

## 17. 实施前必须从本地状态解析的事项

这些不是要求用户重新授权，而是实现第一阶段的审计任务：

- 选择唯一现行父策略 manifest，读取实际仓位、等待窗和成本配置。
- 盘点可用价格、公司行动与质量快照的覆盖范围，确定共同研究起止日。
- 检查哪些历史区间已被策略研究或模型看过；无法证明未见则使用前向验证。
- 确认实际运行日志能支持到哪一层漏斗；缺失历史记录只作规则重建。
- 逐项核查可用于 LLM 的技术特征，不承诺尚不存在的相关性或市场状态字段。
- 锁定研究版本与验证门槛，再计算 challenger 结果。
