# 交易系统升级：实现与验证

更新：2026-09-07。代码已实现，新增策略默认关闭；未启动或重启交易进程，未连接券商下单。策略收益尚未通过真实历史样本验证。

## 审批与执行

所有买入和卖出（含硬止损、结构失效、时间退出和盈利退出）必须先有有效的 LLM 评估，再由用户明确批准。LLM 提供判断，用户作最终决定；无评估结果时无法批准/执行。未确认、提案超时或 LLM 请求失败时不自动下单。卖出拒绝后仍遵守配置冷却。

硬止损现在是高优先级退出提案的触发边界，不是自动平仓承诺。等待期间亏损可能继续扩大。未启用自动券商保护单。

统一入口为 scripts/live_trading/execution.py；旧监控器的无提案买卖入口禁止下单。审批从 pending → approved → executing，提交后进入 submitted / partially_filled / unknown，只有实际全部成交才记 executed。部分成交按实际累计数量和均价更新；拒单、部分撤单保留剩余持仓；响应丢失后凭订单号或提案 remark 查询，禁止盲目重发。

使用 DAY 限价单，执行前重新核验报价时间（默认30秒）、价格漂移、市场状态、持仓、活动订单和账户数据。当前执行器仅允许常规交易时段，盘前盘后暂不下单。审批有效期约束提交时间；已提交订单依照 DAY 有效期可能继续成交。账户不唯一时必须在 live_manager.acc_id 指定账户；自动选择只允许唯一的对应环境美股账户。

同账户同股票的提交以 SQLite 事务互斥。发现已有券商活动订单（包括历史保护单）时不叠加新的退出单；不自动撤单再重下。未知订单持续占用风险并阻断新增风险，重启后恢复到确认页供查看。对账未证明不存在的订单不会自行释放占用。

## 持久化与风险定仓

scripts/live_trading/position_registry.py 使用 data/execution.sqlite3，按 REAL/SIMULATE 的账户 ID 与 DRY-RUN 隔离，保存订单、实际成交、策略归属、初始止损、目标、失效规则及保护线状态。重启恢复最高价和已抬高的保护线，不重新初始化。持仓查询失败不当成空仓。

入场数量由初始止损距离与每股成本预算确定，再受现金、单票金额/比例、产业链风险、账户风险、报价成交量及人工批准的数量上限约束。持仓与未成交订单共同占用预算，事务内重新核算。初始风险不随跟踪止损抬高而释放；部分卖出只释放对应数量的持仓风险。禁止重复买入与亏损摊平。

默认实验参数：单笔0.25%、总风险1.5%、半导体组0.75%、中国组0.5%、投机组0.25%、单票名义价值不超过净值15%；原5000美元配置作为额外金额上限。MU/MULL/SOXL等共享半导体风险组。风险组未知、旧持仓缺初始风险、券商与本地数量不一致时阻断新买入，卖出审批仍可用。不要用默认风险值掩盖未知历史持仓；首次运行需核实已有仓位的交易计划。

## 策略实现

| 策略 | 入场与退出 | 默认状态 |
| --- | --- | --- |
| dip_buy | 已收盘15分钟评分与反转；冻结初始止损/反弹目标，RR与退出使用相同价格；8根已完成15分钟未反弹触发时间退出提案 | 保留现有监控 |
| donchian | 保留55日/1.5倍量基线；执行价距突破位最多0.5倍信号日ATR；开仓后前3个已完成交易日内跌回突破位触发失败提案；日线ATR跟踪 | 保留现有监控 |
| pullback | MA50资格、MA20斜率、20日相对板块强弱、回踩均线、已确认结构低点、已收盘15分钟突破局部高点；结构止损和日线跟踪 | enabled=false，shadow_only=true |
| breakout_retest | 最近突破后回踩未失守，15分钟重新突破局部高点，独立信号编号；结构止损、突破失败、日线跟踪 | enabled=false，shadow_only=true |

回调枢轴按左右各2根确认，避免回填未来低点；板块缺数据时不生成信号。SOXL/MULL/YINN的回调趋势资格可配置为参考SOXX/MU/FXI，产品自身的价格结构用于止损和执行。缩量与RSI没有额外叠加成硬筛选。首版不启用加仓、分批止盈。

日线规则保守排除当天日K；15分钟必须到周期结束才可使用。突破失败和时间退出按实际已完成K线计数，不能将周末当作交易日。失败/盈利退出也需LLM和人工审批。抄底日内数据周期已由旧5分钟改为15分钟，不能直接套用旧回测收益结论。

主要配置：risk_budget、pullback、breakout_retest，以及 dip_buy.time_exit_bars、trend_breakout.max_chase_atr、trend_breakout.failure_sessions。见 trading-upgrade-settings.yaml（不含凭证的配置片段）。
