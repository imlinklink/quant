## 1. 假设与竞争解释

原初始硬止损入场后**永不上移**（只在拆股与分红两处被动调整）。趋势获利之后，回吐空间随时间
持续存在。用「获利激活 + ATR 跟踪」收紧保护，可能减少浮盈回吐与账户下行损失。

竞争解释写在同一处，避免只留一个方向：**回吐是趋势跟随的结构性代价而非缺陷**。收紧保护会把
尚未走完的趋势提前卖出，收益下降可能超过回吐减少 —— H3 已证原止损的尾部控制是有效的
（含止损最差单笔 −1.87R；关闭止损后 −5.54R）。

本轮**不主张**：改 H60、分批止盈、改初始止损距离公式、改定仓/风险预算/池子/市场门/入场条件。

## 2. 规则（唯一改动）与参数

| | |
|---|---|
| 激活 | `H ≥ 入场价 + 1.0 × R0/股`；`R0/股 = 入场价 − 初始硬止损价`（成交时冻结） |
| 保护线 | `P = H − 3.0 × ATR14` |
| 生效 | `stop ← max(初始硬止损, 既有 stop, P)` —— **只收紧，绝不放宽** |
| 时点 | T 收盘算、`effective_session = T+1`；T 的最高/最低价不得用于生成一条在 T 已生效的止损 |
| 跳空 | 新保护线高于下一开盘 ⇒ 按**开盘价**成交，不假定能在保护价成交 |
| 数据不足 | ATR14 缺失或非正 ⇒ 保持已生效保护线、记 `policy_data_unavailable`，**不放宽硬止损** |
| 公司行动 | 拆股：H 与待生效保护线按与 stop 同一比例调整；除息：按每股分红同口径下调 |
| 冲突 | H60 继续有效；跳空止损 / 盘中止损 / 时间退出沿用冻结优先级 |

`H` = 持仓期内**已完成收盘价**的最高值。激活状态是**粘性**的：除息会把 H 按下调，
非粘性实现会在除息后「取消激活」，让已保本的持仓突然失去保护。

**参数不是网格搜出来的**（登记逐条写了理由）：

- ATR14 —— 与既有 `medium_initial_stop` 同一波动率口径，不引入第二套度量；
- k = 3.0 —— 经典 chandelier 倍数，且 **大于**既有硬止损的 2.5 倍 ATR 项 ⇒ 保证保护线只在
  确有浮盈之后才有意义，避免一有浮盈就贴着价格收紧；选 k 而不是在 {2.5, 3.0, 3.5} 里挑，
  是为了不让本轮变成参数搜索；
- 激活 1.0 × R0 —— 与系统全程以 R 计价的约定一致；且因 R0 ≥ 2.5×ATR14，激活时保护线
  ≥ 入场价 − 0.5×ATR14，即**约在盈亏平衡附近** ⇒ 语义是「先保本、再逐日跟踪」。

**看到结果后不得改 k、改激活门槛、加第二条规则或加第二个参数**；要试新值必须另立登记。

## 3. 两臂与口径

**第 1 步（机会级，已执行）**：固定 study 实际成交的全部 201 笔入场；**同一条价格路径、同一股数、
同一费用**，两臂只差保护线是否启用。股数不重算 —— 构造只含这一笔的孤立账户，让定仓**恰好**
取到账本里的实际股数（对不上即抛，绝不静默换规模）。

- A 臂：关闭保护（另用一个「激活门槛高到不可能达到」的同一策略实例取 H，其出场与关闭保护
  逐字段相同，有断言）；
- B 臂：启用上表的保护线；
- 控制项（不过即 `ENGINEERING_BLOCKED`，不出收益结论）：① A 臂复现账本每一次出场
  （原因/日期/价格/净损益）；② 只跟踪实例的出场与关闭保护逐字段相同；③ 从未激活的笔两臂完全相同。

**第 2 步（账户级，仅在第 1 步不是 NO_IMPROVEMENT 时执行）**：同引擎（`paper_engine.step`）、
同空仓起点、同冻输入两臂并排跑，看现金/容量/再入场/回撤阶梯的路径影响。机会级收益差
**不得相加**冒充组合增量。

**数值门槛**（登记 `decision_rules`）：

| 判据 | 门槛 |
|---|---|
| 收益非劣界限（机会级） | ΔΣnet_R ≥ **−8.0R**（≈ A 臂总 R +161.45 的 5%） |
| 尾部风险改善 | 净 R 分布下尾 5% ES 相对改善 ≥ **15%** |
| 最小激活笔数 | ≥ **20** |
| 集中度 | 回吐减少的单一证券 ≤ **50%**，且剔除最大贡献证券后结论符号不变 |
| 2× 成本 | 仍 ≥ 非劣界限 |
| 账户级（第 2 步） | ΔCAGR ≥ −1.5pp；ES 改善 ≥ 10%；`abs(MDD差) ≤ 0.03`；最差单笔不劣 |

判定分档：`EVIDENCE_SUPPORTED`（收益守住且风险改善）/ `RISK_TRADEOFF`（风险改善但收益牺牲，
**只能记为防守选项**）/ `NO_IMPROVEMENT` / `CONCENTRATED` / `RISK_REJECTED` /
`INSUFFICIENT_SAMPLE` / `ENGINEERING_BLOCKED` / `DATA_INVALID`。
